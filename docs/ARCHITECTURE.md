# Architecture — ASCII Atlas

The engine is city-agnostic. Everything specific to a city lives in its city pack (`packages/content/cities/<slug>/`) or is derived from OSM by the pipeline. Examples below use Naga, the first city.

## 2. Renderer public API

```ts
// meta = the city's <city>.meta.json, emitted by the pipeline
const atlas = createAtlas(canvas, {
  tilesUrl: `/tiles/${city}.pmtiles`,      // e.g. /tiles/naga.pmtiles
  theme: 'dark',
  cells: DEFAULT_CELLS,   // map cell width by zoom (density.ts); labels: labelCell, 10×18
  bounds: meta.regionBounds,
  initialCamera: urlCamera ?? meta.defaultCamera,
  year: 2026,
  cityLife: cityConfig.life,             // optional seasonal calendar and daily schedules
  life: { season: 'auto' },              // Today; a pack id previews that season
  lifeHoverPause: 'item', // optional; 'all' restores global Life inspection
  utilities: { derive: cityConfig.streets?.utilities?.derive === true }, // optional; omitted disables
  dialogue: cityPack.dialogue,          // optional validated native/translation catalog
  speech: true,                        // display preference, independent of simulation
});

atlas.setCamera(partial, { animate?: boolean, duration?: number });
atlas.flyTo(target: Partial<CameraState>, { duration?: number });  // duration overrides 0.8–3 s
atlas.getCamera(): CameraState;
atlas.setYear(year: number, { animate?: boolean });
atlas.setTheme('dark' | 'light');
atlas.setSpeech(enabled: boolean);
atlas.setSelected(featureId | null);
atlas.setFocus(focus: LegendFocus | null);            // transient map-class/Life-group focus
atlas.setHighlighted(featureIds: string[]);          // at most 64, e.g. a street's ways
atlas.getFeature(featureId): FeatureInfo | undefined; // once a tile with it has loaded
atlas.setLife(partial: Partial<LifeSettings>);        // includes season selection
atlas.getSeason(): SeasonState | null;               // immutable resolved calendar snapshot
atlas.getStats(): AtlasStats;                         // fps, frame and cell-pass ms, tiles, decode ms
atlas.setUnderlay(null | { kind: 'imagery' | 'historic-map', id: string });
atlas.on('camerachange' | 'hover' | 'lifehover' | 'click' | 'flyend' | 'input'
  | 'classeschange' | 'labelschange' | 'fixtureschange' | 'seasonchange' | 'speechchange' | 'contextlost' | 'contextrestored', handler);
atlas.destroy();
```

`classeschange` sends the classes drawn in at least one on-screen cell (for the legend), and `labelschange` the places, landmarks, and monuments whose names are on screen (`{ featureId, name, kind, lngLat }`, for the "Places in view" list); both fire only on change. `contextlost` and `contextrestored` bracket a lost WebGL context (see §3). `input` fires when the visitor moves the camera (drag, wheel, pinch, or keys; not clicks or hover), which also ends any flight; a tour pauses on it. `hover` and `click` carry `{ featureId, feature, point }` (`click` also `lngLat`), where `feature` is the slim `FeatureInfo` the tile worker recorded: class, name, subdivision (and whether it is approximate), landmark id, kind, and height. The package also exports `legendEntries(theme, zoom, present?)` and `CLASS_LABELS` for the legend.

Seasonal decoration uses `AtlasOptions.cityLife.seasons` and optional `LifeSettings.season` (default `auto`). `getSeason()` returns a stable, immutable `{id,title,status,note?,labels}` snapshot or null; `seasonchange` fires only on selection changes. Real city date resolution runs initially and with sun/clock updates, independently of fixed time and historical year. Selection invalidates fixture inputs and stale Life agents; a valid terrain snapshot in an in-flight reply is still accepted. Hard clears, disposal and worker failures invalidate the entire reply. This preserves terrain guards without moving the camera or resetting ordinary populations.

The web app owns app state (Zustand) and pushes it into the renderer. The renderer emits events back. The renderer never reads the URL or the DOM outside its canvas, and it knows nothing about specific cities. Switching cities destroys the atlas and creates a new one with the other city's tiles and meta.

`AtlasOptions.utilities?: { derive: boolean }` controls static overhead hardware independently of Life. `fixtureschange` reports `{ streetlights: boolean, trafficSignals: boolean, utilities: boolean }` when viewport-packed hardware changes; `utilities` indicates nontransparent packed marks, before the shader's surface mask. `legendEntries` accepts that fixture report, including an omitted `utilities` field for older callers. Utility record version 1 is unchanged: pipeline validation remains strict, while the worker skips malformed or unsupported individual records using a Zod-free shape validator, retaining ordinary tile geometry.

**City meta** (`<city>.meta.json`, generated): `slug`, `name`, `subdivisionLabel`, `languages`, `bounds` (the city boundary bbox), `regionBounds`, `defaultCamera` (centered on the city config's `focus` feature at its zoom, else the boundary centroid), `yearRange` (earliest year with data to the current year), and `attribution` (extra credits the city's layers need).

## 3. Rendering pipeline (per frame)

Pack-defined `life.seasons[].fireworks` supplies a label and a validated subset of `peony`, `chrysanthemum`, `ring` and `willow`. A lazy instanced pass after glyph drawing and before street text reuses the map atlas and one immutable buffer capped at 50 shells / 8,600 particle quads (137,600 bytes). A per-context seeded generator samples each new launch's visible world site, height, visual seed and independent pause after the previous smoke expires. Regular heights are 80–220 illustrative units; the extra distant high slot is 460–560. Rise time is `0.55 + height * 0.005` seconds; sparks/smoke last 4.4/4.8 seconds, followed by a 0.25–3-second pause. Full initial intervals are sampled to prevent synchronized entry waves and lulls. The atmospheric eye height is `320 / 2 ** (zoom - 19)`; it descends from 320 at z19 to 80 at z21. A launch is visible only while its height is below the eye. Projected centers and extents use `eye / max(eye - height, height * 0.15)`. Radius is the larger of a modest `30 + height * 0.1` CSS-pixel legibility floor and projected `height * 0.35` extent, capped at 520 CSS pixels. Fixed visible launches never shrink on approach. A smooth altitude opacity fades them over the final 35% of their height separation, reaching zero when the eye passes below the burst. Higher breaks disappear before lower ones; there is no z16 high-slot cutoff or substitution of lower launch heights. Spark ink is 5–12 CSS pixels wide according to projected radius, independent of map-cell detail. Ascent, sparks and smoke share packed altitude opacity. All 49 regular launches remain cached, but the regular admission ceiling falls quadratically from 49 at z16 to four at z20, then linearly to zero at z21 (rounded up). Including the extra high slot while below the eye, total ceilings are 50/31/17/7/4 at z16/17/18/19/20 and two at z20.5. Selection keeps the nearest surviving regular launches and separately reserves the high launch until its altitude cutoff; a culled high slot does not admit an extra regular launch. Heights and clocks remain unchanged. At z21 the pass and legend entry are skipped. Packed center/seed/radius, age/rise, visibility/ink width and source indices are reused in fixed arrays; selection swaps all fields together without frame allocations. Two instanced draws submit only admitted smoke and spark prefixes, with smoke under tails/tips (at most 688 particles at z20). Vertex shaders handle ascent, expansion, tails, fade and wind; expired particles collapse to off-screen degenerate quads. There are no per-frame vertex/texture uploads, new glyphs, tile records or Life-worker data. Place-label halos stay readable. The effect is independent of Life, selected hour and wind strength; reduced motion freezes poses, disables drift and reframes only after a complete pan away. GPU resources follow normal destruction/context recovery; inactive packs and hidden zoom levels allocate nothing. The sky projection is illustrative and does not change the north-up map camera or represent calibrated physical metres.

1. **Camera → visible tiles.**
   - Compute the view frustum in mercator space.
   - Select tiles at `floor(zoom)` for the view, plus a 1-tile margin.
   - Use overzoom for zoom levels above the max tile zoom (z16 recommended).
2. **Tile decode (worker).**
   - Fetch via `pmtiles` range requests, then decode with `@mapbox/vector-tile`.
   - Convert to typed arrays per layer (triangulate polygons with earcut, keep lines as polylines).
   - Runs in a Web Worker; results are cached in an LRU by tile key.
3. **Cell pass (GPU).**
   - Render geometry into an offscreen framebuffer whose resolution equals the cell grid (e.g. 384×108 for a 1920×972 canvas at 5×9).
   - Uses MRT (multiple render targets):
     - `classTex` (RGBA8, red only: feature class id; RGBA so the legend's readback needs no conversion)
     - `attrTex` (RGBA8: height, shade, time-visibility, flags)
     - `idTex` (RGBA8: 32-bit feature id packed)
   - Lines are drawn with width in cell units so roads stay 1 cell wide at every zoom.
4. **Neighborhood pass.**
   - A fragment shader samples each cell's 3×3 neighbors in `classTex` to get road connectivity bits (N/E/S/W and diagonals).
   - The bits index a lookup table of box-drawing glyphs.
5. **Glyph pass.**
   - Full-resolution draw of one instanced quad per cell.
   - Each quad samples the glyph atlas (a canvas-generated monospace font texture, SDF optional) at the chosen glyph and colors it from the theme.
   - Time and animation effects (water shimmer, type-in/dissolve masks, selection glow) are applied here.
6. **Labels.**
   - CPU placement on the cell grid with greedy collision placement: selected, hovered, then rank, retained visible names, retained offscreen names, newcomers, and feature id. Rotated streets try their road-aligned slot first; typed remembered horizontal slots precede the other horizontal fallbacks.
   - Per-target memory retains accepted slots through pans; only retained layouts get a three-cell margin beyond the fully visible cell bounds. Tile copies are filtered for eligibility before consolidation: onscreen text, deeper source-tile geometry, an eligible accepted copy, then longest run and geographic ties. Focus-only frames rebuild the overlay without rasterizing cells or adding a crown frame.
   - Place labels use the glyph overlay. Street labels use a batched glyph-quad pass over it, rotating whole words in screen pixels with the same atlas, theme, halo and deterministic dissolve. Their conservative rotated bounds participate in the same collision grid; short straight runs fall back to beside placement.
7. **Picking.**
   - On hover or click, read back a single texel from `idTex` at the pointer cell, asynchronously (`readback.ts`, see the notes below). A feature that fails the `interactive` option (the web app passes "is a landmark") counts as a miss: it is neither highlighted nor reported.

Rasterization runs only when the camera, year, or tiles change. While watched, animation redraws the crown, Life, lighting, select and glyph passes at up to 30 Hz when idle, and on every animation frame for 500 ms after input (`pacing.ts`). Reduced motion or an unwatched map pauses autonomous animation; dirty views still redraw.

The glyph program compiles inactive legend-focus and candle-clock features away. It starts with the minimal variant, so normal maps avoid the inactive halo loop and clock sampler. After the first draw and one second without camera/pointer input, idle tasks prewarm the focus variant first; clock combinations warm only when the existing Life packing scan finds candle actors. This avoids compiling unused clock shaders on ordinary maps without adding an agent scan. The pending warmup can upgrade when candles arrive, and compilation remains serial. With `KHR_parallel_shader_compile`, completion is polled before link status and uniform introspection; otherwise at most one variant compiles per idle turn. An interaction before completion finishes the needed link through the normal synchronous path, so cold interactions can still hitch. Pending links and scheduled tasks are cancelled on context loss and disposal. Each variant is compiled once per context and released with the other programs; context restoration starts a fresh cache. Switching focus or clock-texture availability selects the matching program without changing compositing or simulation behavior.

**Hover and legend focus hardening.** `LegendEntry.id` and the exported `LegendEntryId` identify entries independently of their labels: canonical `class:` identities preserve explicit marker/building and crown/trunk grouping, `life:` identifies simulated groups, and `info:` identifies explanatory entries. Legend merging, transient selection, React keys, synthetic Life descriptors and local subdivision wording use those IDs. The always-mounted HUD resolves its list and clear control from one current entry and refreshes the renderer descriptor as class membership changes. Measured header clearance is published as CSS properties for legend scrolling and expanded mobile sheets, following the attribution-height pattern. Tooltips measure on label/element-size changes and use a pure placement helper for pointer/visible-viewport changes. Hover candidate keys include packed class and masked agent permission bits, excluding cosmetic flags. Pending batches, confirmed visibility and held inspection share a request-age limit: `min(1000, max(250, 4 * recentFrameIntervalMs))`, using the maximum of the last four active hover-update intervals. This permits a two-frame read and its renewal on slow devices while bounding stale evidence under saturated queues. Lifecycle invalidation resets cadence and rejects old callbacks. No hover-frame geometry or label callback is constructed without a pointer.

**Life inspection pause.** `AtlasOptions.lifeHoverPause?: 'item' | 'all'` defaults to per-item inspection. Worker and inline worlds assign stable actor IDs independent of raster indices and optional profiling identities. A static, non-enumerable symbol slot on each simulator owner holds a typed record fenced by registry and reset epoch, keeping object shapes stable across worlds. A weak fallback handles the rare owner shared by separate registries. Visible views carry numeric IDs across the worker boundary without owner-record references. A bounded latest-visible lookup accepts a desired ID and monotonically increasing command revision before stepping. Reused numeric admission stamps compact capped lookup entries in place; unseen or capped selected owners are released. Replies carry no unused inspection acknowledgement. Bird clock lookups activate only while bird owners need retained offsets; off-screen rejoin admission uses a separate count of pending bird snapshots. Completed recovery removes its snapshot but preserves the owner's gait offset. Permanent tile retirement removes these memberships; frozen tiles retain them for revival. Host generations reject old world replies and identities. Held movers retain collision and junction occupancy while skipping movement, gait and local scene timers. Shared traffic signals, fish, weather and other actors continue. Logical groups share one identity, including the pagoda, all rope-connected towing columns and their crews. Independent escort boats and crowds keep separate identities; individual birds retain their visible pose and steer back toward their moving flock at species speed after release. Actor clock/progress offsets prevent catch-up; live procession offsets survive replay controls and reset for a new real occurrence.

The hover controller selects an actor only after asynchronous surface verification. It renews both positive and negative evidence from 125 ms using generation, actor, geometry and subcell keys, independently of unrelated raster revision changes. Callbacks record only captured request evidence; the next update validates it against current owners and agents, even when raster buffers were repacked in place. Moving within the same held item preserves its tooltip while a new subcell is verified, without extending evidence age. Hover and speech share the surface predicate and three-read helper and reserve two slots in the eight-read queue. The existing bounded cadence-aware evidence expiry still applies. Camera/input, geometry, settings and visibility/context invalidations clear inspection. Unchanged accepted worker frames retain raster owners, draw count and revision without repacking or uploading until their paired frame, target, placement, camera/density, theme, sun or focus changes.

Carried candles use a lazy, nearest-sampled `RG32F` texture: R identifies the ink clock and G the winning candle-pool clock. Tokens use `ORDINARY_CLOCK` (`-1`) for ordinary time, nonnegative values for accumulated pause offsets, and `heldClock(time)` (`HELD_CLOCK_BASE - time`, with base `-2`) for held time. Packing and GLSL share these definitions from `life/effect-clocks.ts`. Only candle shader paths sample it. Life packing records only clocked candle writes and resolves their final raster owners. Ink/R and lighting/pool/G writers track previous and current token cells independently, so an idle lighting pass keeps its pool channel. Winning pools replace tokens, including ordinary-time winners. A separate content revision suppresses unchanged uploads despite unrelated raster revisions; ink clocks update even in daylight. Lamps, traffic signals and environmental effects retain their shared clocks. The texture adds no render pass and is released when no clock tokens remain, when targets resize, on context replacement and on disposal. Identity metadata remains on the CPU; no GPU ownership texture is added.

**Rollback.** Set `NEXT_PUBLIC_LIFE_HOVER_PAUSE=all` when building the static web export, then rebuild and redeploy it. This restores the prior global pause and bypasses per-item identities, command handling and candle clock textures. The renderer option `lifeHoverPause: 'all'` provides the same fallback to other consumers. Unset or empty settings default to `item`; any other nonempty value besides `item` or `all` fails when Next loads its build configuration. Changing this build-time variable does not change an already deployed export. Configuration rollback is the supported recovery path: later merges mean a source revert is not a conflict-free one-commit operation. Inspection is transient and does not change saved view/preferences.

**Inspection diagnostics.** `pnpm perf:inspection --scratch=<task-folder> --case=transit/1 --runs=10 --samples=500` writes `inspection-cpu-comparison.json` and complete runtime snapshots into the supplied task folder. The default baseline is main commit `a427b229e1af9ced1464135120e73a73d6e667b5`; use `--baseline=<commit>` explicitly to compare another revision and `--label=<name>` to retain several reports. Snapshot helpers share source copying and workspace alias/link rules, reject mismatched lockfiles, and record normalized source hashes. The tool compares simulation/visible/packing CPU, with an unchanged baseline control and global fallback; it does not measure worker cloning, speech-grid copies, texture uploads, browser FPS or hardware GPU time. Ordinary and held median/p95 growth must remain within 5%, with control drift within 5%; an unstable control is inconclusive. Independent-worker captures are needed to audit heap/GC sensitivity before accepting a marginal result.

CI emits a Playwright JSON report for each shard and checks `stats.duration` against 200,000 ms after the suite, excluding export preparation. Missing/malformed reports fail the check. Playwright's 240-second global stop and the six-minute CI job cap remain unchanged. Browser assertions belong in the existing core smoke flows; controller logic remains in Vitest.

**Implementation notes (Phase 1).**

- Steps 4 and 5 are split differently: a cell-resolution *select pass* does the neighborhood lookup and all glyph selection, writing one glyph index and class per cell, and the glyph pass is a single full-screen triangle that reads that texture. It gives the same result as instanced quads with less work.
- Class priority is the cell pass's depth value, in tiers; within the building tier, taller features win, so height-less grounds (e.g. a school campus) sit under their buildings.
- The cell grid is anchored to the world, and the glyph pass shifts it by the sub-cell pan offset, so panning scrolls smoothly instead of re-quantizing.
- Zoom follows the 512-px tile convention (`@math.gl/web-mercator`, MapLibre).

**Implementation notes (Place-level detail).**
- Sourced `SiteDetail` records preserve an OSM area's selection identity while replacing its ground class with paving. Rounded seating footprints and raised planting beds enter the existing walking obstacles and full-body clearance. Bench anchors retain compass headings; authored walks enter the walking graph without painted path glyphs. Stone footprints use the `seating` class, below crowns and above grass; closed seating lines retain polygon holes and outward pause anchors. The `shrubs` area class adds blocked planting without creating crowns or roosts. Both have subcell edges; stone seating also uses connected wall glyphs at Place detail, independent of its sub-meter height. The `planting` class draws sparse green tufts over brown soil using a separate optional theme `fillColor` (other styles default to their glyph color). Crowns remain opaque above all ground detail. Multi-head lamps use the static fixture pass and remain visible with Life disabled. Optional per-head `lampStyles` worker bytes distinguish compact lanterns from legacy streetlights; omitted bytes keep the streetlight default. Heads on the same authored lantern post share hardware ownership at their base. Per-class tables have 56 rows, including five reserved glyph rows; shader bit-mask lookups reject class ids above 31 rather than wrapping their shifts.
- **Overlay.** Labels are drawn from an RGBA8 overlay texture on the cell grid (a 16-bit glyph code per cell), over the map in the glyph pass. Map/life glyphs use ten-bit indices: the red byte stores the low eight bits and the green byte stores a six-bit class plus the two high glyph bits. Label characters use their own atlas.
- **Top-down only.** The map never mixes in front views: landmark detail comes from plan-view `building_part` footprints (pipeline step 04, from the city pack's `plans/`), which the renderer treats like any building (outlines, priority by height).
- **Outdoor structures.** Optional `SiteDetail.structures` supplies polygon beams, supports, platforms and roof contours. Timber uses the appended `building_woodwork` class; stone and roof contours reuse `building_part`, with the existing fill, outline, subcell edge and crown-height pipeline. Timber has no lit windows. `detail_overhead` excludes elevated geometry from both ground polygons and walking outlines while retaining its visual coverage; supports and platforms remain obstacles. No render pass, texture, public renderer method or city-specific renderer code is added.

- **Walkable terraces and flag cloth.** Outdoor structures with `material: 'paving'` use walkable paving and a terrace variant. A small depth bias keeps these surfaces above ordinary paving; connected outlines from z18 distinguish non-overlapping stair treads. `FeatureInfo.parentId`, from `detail_parent`, resolves pointer selection to the original plaza while outlines retain their own feature identities. Projected flag cloth envelopes are cached with static hardware; bounded cloth cells are cleared and restamped at up to 15 frames per second from renderer time and wind strength, independent of the Life clock. Static fixture ownership protects masts, lamps and signals. Flag-only updates upload the fixture texture without rebuilding the signal-light lookup; reduced motion freezes the cloth. The existing glyph, texture and pass formats are reused.
- **One matrix path.** The camera is always flat and north-up (the map never tilts or rotates), so the cell pass maps tile units to the world-anchored cell grid with a per-tile affine matrix.

**Neighborhood identity.** Frontage kinds are shared validated data. The pipeline assigns shops to the smallest containing footprint (stable OSM id breaks ties), retains otherwise unrendered shop areas as interior markers, and computes geographic shop anchors before clipping. The tile worker owns each light by its anchor's half-open tile; buffered commerce is deduplicated by source identity, with deterministic 150-entry caps. Old archives retain the geometry-derived fallback. Awning paints use a per-class uniform table rather than a 32-bit mask, preserving station classes and ten-bit glyph indices. Commerce admission uses separate seeds after legacy settlement; walking still requires mapped pedestrian routes.

**Life layer (SPEC.md §4).**
- **Residency and zoom continuity.** `LifeWorld.sync(tiles, focus?, view?)` snapshots active/retired donors before admission. It revives original `TileLife` instances for up to eight clamped simulation seconds and caps retirement at 24 tiles, oldest first. `sync([])` retires; `clearTiles()` removes both populations and terrain/rail/junction caches while preserving the world clock and procession state. Retirement sheds crossing dependency caches, and retired tiles never step, draw, collide or contribute arrival occupancy. Geometry for an active key is immutable until a hard clear.
- **Ownership and adoption.** The finest live tile owns each half-open geographic footprint. Canonical quadtree masks record ceded donor regions, including rejected transfers, and let existing parents reclaim uncovered territory without stale re-donation. Cross-zoom vehicle/boat/train projection uses a lazy 16 m segment grid, stable line IDs when present, directed bearing/one-way/craft checks and detached previews. Admission fills seeded per-kind quotas or replaces an eligible nearest resident only in gained territory; carried agents and service/passenger relationships are protected. The 600-mover tile cap applies to trains too. Commit preserves object identity, scales speed/velocity by `perMeter`, transforms train trails/station coordinates, clears geometry-local plans and consumes no random draws. Ground collision probing ignores the source owner and prospective replacement only. Masks also govern stepping, traffic/junctions, interactions, parked/vendor/flock output, and mixed-zoom train lookahead/handover/arrivals. The legacy same-zoom train handover remains unchanged.
- **Host lifecycle.** Geographic focus, viewport bounds/CSS spawn margin and explicit clearing travel through inline/Comlink hosts. Without view context, synchronization retains the eager compatibility path. With it, `LifePreparation` owns at most eight queued jobs, one running iterator and four private ready tiles. Visible geometry precedes margin geometry. A shared generator drives both eager and staged terrain, route, walking graph, scene, population and initial settlement work without changing random-stream order. An accepted simulation frame precedes preparation (2 ms per slice). Private iterators continue through yielded timer turns between display frames, preventing slow drawing from starving loading; those turns never simulate or activate agents. The first visible ready tile commits promptly, followed by bounded batches. Hard clear/dispose cancels scheduled turns. The bounded ready set shares terrain preparation and serialization buffers, then commits atomically at an accepted frame boundary. Current occupancy is checked again at activation and traveler birth. Coarse/fine predecessors retain ownership until overlapping replacements are ready; obsolete jobs are canceled. Camera-only changes retain geometry progress and valid in-flight frames. Empty views, hard clear, traffic replacement, context recovery and disposal cancel pending work; expired retirees cannot revive through a stale ready job. Worker geometry bookkeeping stays desired-only; returning keys resend geometry while the retired simulation retains its original clone. Agent frames retain their corresponding immutable cell guard on worker and inline paths. Worker failure starts the existing fresh inline fallback. `testing/scenarios.ts` includes frozen scenes, pending seeds/credits, retirement times and ownership masks; scheduler inspection returns detached bounded counts. The legacy steady-state snapshot shape remains available for exact comparisons.
- **Seams and replacement stock.** Cars/boats reserve destination clearance before movement and change owner after all tiles have stepped, preserving their object and physical speed without a boundary turn. Failed destinations brake/wait; junction holds and waiting age are rebound until rear clearance. Ordinary walking groups use mapped paths/plazas, 2 m per-member pose tolerance and whole/swept footprint checks. Scene participants remain local. Carries consume inert pending seeds before hidden residents and protect previously visible residents. Births try at most 32 deterministic round-robin candidates per accepted step, prefer full offscreen bodies beyond max(12 m, two CSS cells), and use safe route/view-edge entries after one simulated second with 4/tile/s and 16/world/s bounded credits. Pending actors do not step, draw, collide, reserve scenes or donate; no continual population refill occurs.
- **Continuity profiling.** Profiling adds transfer, birth, revival and classified rejection counters plus weak origin-tile/incarnation/ordinal identities. One selected visible vehicle produces at most 4,096 trace records; tests/debugging can select an identity. These values never affect simulation or random streams. `acceptedFrameAge` uses the main posting clock for the last accepted frame; stale replies cannot merge diagnostics. `prepareSlice` reports individual slice percentiles while each sample retains their complete CPU sum, including work between worker replies; `activation` measures the atomic commit, with reset/worker/inline coverage. Yielding terrain preparation avoids measuring the idle time between slices as CPU.
- Worker life geometry retains carriageway and crossing quads independently of street-marking zoom, mapped sidewalk centerlines with side-specific widths, and parking exclusions from crowns/tree rows and woods. Sidewalk lines are appended after existing lines to retain their identities; sharp joins use bounded miters or bevels, with unsafe connectors rejected by road access. Metric road preparation is shared per geometry and scale by the walking graph and vendor prefilter. The world caches forbidden pieces in owner-local meters, subtracting neighboring crossing quads only when a road's overlapping crossing dependencies change. Group queues, swept ground clearance, and whole-agent ASCII cell rejection share these rules. Road-centerline walkers and inferred roadside graph edges are omitted. Vendors cannot use crossing cutouts and are revalidated on terrain changes, releasing customer queues when removed. Parked vehicles overlapping buffered tree cover are removed, including across loaded tile seams; moving vehicles remain packed and the glyph shader lets actual trunks, crowns, and woods occlude their cells.
- Interaction data travels with `LifeGeometry`: stable, tile-owned site anchors and mode bits, plus building, water, and barrier outlines. `life/navigation.ts` constructs a bounded tile-local walking graph from mapped paths, sidewalks, crossings, and plaza outlines, rejecting blocked connectors. `life/interactions.ts` reserves existing movers for approach, queue, purchase, boarding, shelter, and return states. Searches are staggered across frames; seeds are separate from traffic and bird random streams. Queues and reservations disappear with their owning tile. Scene movement uses the ground collision guard and retraces its approach to resume ordinary movement.
- People, cats, and dogs share permitted walking lines (paths, mapped sidewalks, and plaza routes), crossing signals, swept footprint clearance, local scene guards, and whole-agent ASCII cell rejection. Animal bodies conservatively cover their square sprite masters. Animals settle after legacy ground actors so they cannot displace existing people or traffic. Spawn densities and speeds use `life/config.ts` spawn rules; species behavior tuning lives beside people tuning. Cats use a separate seeded stream and at most six slots per tile inside the existing 600-mover cap. Their procedural glyphs reuse the people layer; map glyphs retain the existing ten-bit encoding. Rain rings and occasional fish are world-anchored effects in the existing glyph shader (`life/water.ts`), adding no render pass. Fish require Life and zoom 18; reduced motion disables both effects.
- The tile worker also emits a tile's `LifeGeometry` (`life/geometry.ts`): road, path, plaza-outline, and river polylines in tile units (roads with their width in meters, so each vehicle keeps to a lane on its half: `life/config.ts` `laneOffset`), plus roost points for birds (park, woods, and water centroids inside the tile) and parking stalls (rows along each parking lot's principal axis, inside the lot and the tile: `raster/geometry.ts` `parkingStalls`). Loaded tiles keep it on the main thread.
- `life/simulate.ts` is pure TS. `LifeWorld` holds a `TileLife` per drawn tile (z13 and deeper), synced when the cell pass runs and seeded from the tile key. Movers walk their polyline in tile units at meters-per-second speeds and pick another usable line meeting at a junction (an endpoint index per tile), else U-turn except for one-way road vehicles, which brake and hold. Their terminal room subtracts half the vehicle length and `FOLLOW.minGap`; movement clamps use the same room, retain an incoming cursor, and protect initial-placement and collision retries from wrong-way reversal. Flocks circle a roost. Before moving, each vehicle and boat targets the nearest overlapping leader on its line or planned exit. Reused target/cap arrays combine headway, comfortable braking, signals and transit stops. `motion.ts` bounds acceleration and routine braking, with immediate safety caps; `Mover.v` records accepted path distance after clearance retries. `curves.ts` supplies quadratic fillet poses shared by drawing and clearance while route cursors stay on their centerlines. Parked vehicles are spawned once per tile on lot stalls and along the curbs of some wide roads, from their own random stream; those roads drive on the width left between the parking strips. `step(dt)` clamps `dt` to 100 ms and moves only what could be seen: the kinds that show at the zoom, and, given the view's bounds, the agents within 100 m of them (`STEP_MARGIN_M`). The others wait where they are, except trains, which run on from tile to tile. `visible()` places only those within 30 m of the view, and applies the zoom bands and time-of-day activity (`life/config.ts`), keeps movers inside their own tile (tiles overlap in their buffers), and caps the count.
- **Ground clearance.** Ground clearance uses a shared metric spatial hash over loaded tiles. Parked vehicles and vendor carts reserve oriented footprints; moving ground agents test both destination and swept intermediate bodies, including walkers in a group. Polygon bounds reject distant bodies before narrow-phase tests, and a half-diagonal-padded swept rectangle skips terrain queries that cannot hit. Static building and water polygon bins are cached until the tile set changes; transformed building, water, tree and road polygons are reused per tile and metric origin when rebuilding those bins; road traffic can cross bridges over underlying water. Parking checks actual polygon rings, including holes, rather than only spot centers. Junction envelopes derive from intersecting road segments and their widths. - Every drawn frame, the **life pass** (`passes.ts`, packing in `life/draw.ts`) projects the agents with the grid placement's `toCell` and writes an RGBA8 `lifeTex` on the cell grid (glyph index, life class id, agent kind bits, and for vehicles and boats their paint in alpha bits 0–3, their part in bits 4–6, and bit 7 for parked, lamps off). **Implementation notes (Phase 2).**
- **Crossfades.** Each frame the cell pass gets every class's visibility (`bandVisibility` of its `CLASS_ZOOM` band, 0–1). A partly visible class keeps only the cells whose per-world-cell hash falls under its visibility and discards the rest, so it dissolves into the layer beneath and the dither stays put while panning.
- **Region layers.** The sea, coastline, terrain, and admin boundaries are ordinary classes: terrain bands nest, and the band number in the height byte makes the higher band win (the `ramp` glyph kind picks `. : - = + * # %` from it). Admin lines are see-through for outlines and curbs.
- **Picking.** The pointer maps to a cell by inverting the glyph pass (`picking.ts`). After a frame is drawn, one texel of `idTex` is read, at most once per frame, without blocking: `readback.ts` issues `readPixels` into a pixel-pack buffer with a fence, and copies the data out a frame or two later, once the fence has signaled. A read from render targets that were recreated in between (a resize) is dropped. The tile worker sends a `FeatureInfo` for each feature it registers, so an index resolves to a feature without keeping tiles on the main thread.
- **Selection.** The select pass compares each cell's feature index with the hovered, selected, and highlighted indices and writes a state into the glyph texture's spare channel; the glyph pass brightens hover and draws the accent color (with a shimmer for the selection, unless reduced motion is on).
- **Fly-to.** Flights follow van Wijk and Nuij's zoom-and-pan path (as MapLibre's `flyTo`), eased, 0.8–3 s (≤0.3 s with reduced motion). Any input cancels one.
- **Zoom-out limit.** On every resize, the minimum zoom becomes the zoom that fits `regionBounds` in the view, and the view keeps the whole screen over the region.

**Implementation notes (post–Phase 2 hardening).**
- **Legend of what is on screen.** After a cell pass (at most every 250 ms, and always after the last one), the on-screen part of `classTex` is read back the same asynchronous way, and the set of class ids present is sent as `classeschange`. `legendEntries` drops a zoom-visible class that the cell pass draws but that isn't present.
- **Labels fade.** Labels use the classes' fade (`bandVisibility`, half a level at each band edge). A partly visible label keeps its whole box for collision, but only the share of its cells (text and halo) whose hash of (label, cell) falls under its visibility, so it dissolves like a class and the pattern holds while panning.
- **Lines claim their vertices' cells.** GL_LINES skips a segment that never leaves one cell's center diamond, so a river of many short segments broke into dashes at the City level. The tile worker also emits a point at every line vertex, which always covers its cell.
- **Lost context.** On `webglcontextlost` the renderer calls `preventDefault()`, stops its loop, and forgets every GPU handle without deleting it (the tile cache drops its meshes, and tiles that arrive meanwhile). On `webglcontextrestored` it recompiles the programs, rebuilds the glyph atlas and render targets, and asks for the view's tiles again; feature indices survive, since the worker keeps its id registry.

**Implementation notes (legibility: two colors per cell, sub-cell edges).**
- **Fill.** The select pass writes a fourth byte, the class whose fill is the cell's background (`fillClass`: the cell's own class, except carriageways drawn as 1-cell lines). The glyph pass mixes the background toward that class's color by its `fill` strength (`GlyphTables.fills`), then draws the glyph over it. Agents are drawn over the same fill.
- **Sub-cell targets.** The cell pass runs its ground draw a second time into class, attribute, and id targets at `SUB` (2 × 3) samples per cell (`CellTargets.sub`). The crossfade hash divides the fragment position by the sample count, so both resolutions keep the same cells.
- **Edges.** For an empty cell or an area cell (`subcellClasses`) that isn't walled, the select pass picks the foreground feature (the cell's own area, or a building among the samples), builds a 6-bit mask of the samples whose id matches it, and on a partial mask emits that sextant (two glyph-table rows, `SEXTANT_ROW`) with `EDGE_STATE` set in the state byte and the first other sample's class as the fill. The glyph pass draws an edge's ink between the feature's fill and its color (`EDGE_INK`).

**Implementation notes (cell size by zoom).**
- **Steps.** `density.ts` holds the schedule (`DEFAULT_CELLS`), `cellStep` (with `STEP_HYSTERESIS`), and `detailZoom`. Each frame, `index.ts` checks the camera zoom's step; a new step marks the size dirty, and `resize` switches to that step's map glyphs (atlas and glyph table, built the first time and kept per step until the theme or pixel ratio changes, or the context is lost) and recreates the targets at the new grid size. The grid re-quantizes at a step change; the step edges fall mid-zoom, while every cell is already re-rasterized.
- **Two grids.** Labels have their own grid and atlas (`LabelGlyphs`, `labelCharacters` at `labelCell`), so they stay 10×18 while the map shrinks. `placeGrid` places either grid from its cell size (world-anchored); the overlay texture has the label grid's size, and the glyph pass finds a pixel's label cell from `u_labelCell` and `u_labelShift`. Map glyphs (`mapGlyphs`: styles, walls, sextants, vehicles, and people) have the map atlas to themselves and use ten-bit glyph indices. Picking, the life layer, and the legend readback use the map grid.
- **Detail zoom.** `View.detailZoom` goes to the cell and select shaders as `u_zoom`, so `OUTLINE_ZOOM`, `ROAD_AREA_ZOOM`, and `ROOF_ZOOM` are reached sooner with smaller cells; class visibility, labels, and life bands use the camera zoom. Below 8 device px, shade blocks lose their one-pixel gap (`SHADE_GAP_MIN_WIDTH`), which would otherwise draw a mesh over buildings.

### Human speech

Encounter reach is the larger of its original limit and the pair's combined rendering clearance plus two metres; third conversation members use the same rule. Minimum separation and guarded facing still apply. A failed facing admission rolls back and retains its accepted chance for a retry at most once per simulated second, charged against the existing eight-check scan budget. Lost eligibility, separation, idle state or suitable weather discards pending admission. Rejected chances remain remembered for their approach or idle episode; retries never reroll them.

The optional city-pack dialogue catalog is validated by `shared/dialogue.ts`. Static pages project it to a derived `RuntimeDialogueCatalog` before crossing the client boundary; editorial sources remain in the pack. Browser-safe helpers in `dialogue-options.ts` compile IDs, kinds, periods, turns and scene metadata into text-free worker choices. `Moments` uses a separate seeded dialogue stream and attaches clone-safe `{ id, exchangeId, line }` cues to existing visible people. Native phrases and translations remain in the app. Speech preferences have their own per-city local-storage key, outside URL view state; toggling speech calls `Atlas.setSpeech` without reseeding or restarting Life.

Final Life packing optionally fills a reusable CPU ownership grid, restoring ownership along with texels when a ground stamp is rejected. Bird shadows have no actor ownership. `SpeechController` finds a surviving owned speaker cell and checks the same surface predicate as the glyph shader using one asynchronous batch of three texels (coarse class, sub-cell class and height). It shares the existing eight-read cap, creates no GPU targets, bounds candidates to six/four and output to three/two using canvas width, and rejects stale camera, raster, ownership or cue results. Refresh prioritizes displayed speakers and one rotating spare, normally after 400 ms. A bounded history of eight batch latencies advances refresh when needed to finish a rotation before the one-second confirmation expires. A batch requires three available slots plus two reserved slots for picking and class reads. Confirmation expires one second after readback completion, with immediate invalidation for a negative result or changed camera, ownership or cue. Pending batches also have a one-second watchdog. Offscreen and label-covered anchors are excluded. Camera changes, Life off, reduced motion, heavy rain, hidden tabs, context loss and disposal clear the overlay. CPU and shader composition share Life occluder classes; the app does not apply a second bubble cap.

`speechchange` carries CSS-pixel anchors to a small imperative DOM overlay. It resolves the city catalog, keeps native and translated `lang` attributes, and measures only changed phrases. A 200 ms layout check handles panels opening around stationary speakers; map input passes through the overlay and ambient lines are hidden from screen readers. HUD controls remain accessible. No per-frame app-wide state writes are needed.

Completed GPU reads are delivered after drawing and issuing prioritized pick/class queries. Replies store their captured candidate key without reading grids that have already been redrawn. The following speech update removes keys absent from the current frame and publishes current positions; cancellation serials discard obsolete batches. This keeps blocking work from consuming freshly completed confirmations and avoids combining old agent indices with new ownership grids. Pending speech requests date their one-second watchdog from issuance, and publication uses the current clock rather than an earlier animation-frame timestamp.

Speech and human moments share `SPEECH_ZOOM`. Optional greeting-period metadata is text-free and passed identically to worker and inline initialization. ## 4. Glyph selection rules

The rules live in `glyphs/select.ts` and mirror the shader logic, so they can be unit-tested on the CPU.

- **Water:** short crests of the second glyph drift east along each row, with rows offset and moving at one of two speeds and some crests skipped; reduced motion holds the pattern still. Rivers and streams (styles with the six stroke glyphs) draw a 1-cell-wide run that isn't horizontal as a stroke instead: `(` and `)` alternating down a vertical run, `╱` / `╲` for a diagonal one, judged from which neighbors are any water class.
- **Buildings:** luminance from shade × height factor maps onto the `░▒▓█` ramp.
- **Roads:** connectivity bitmask → box-drawing LUT. Road hierarchy picks a single-line or double-line set.
- **Area fills** (farmland, parking, pitches): patterned by `(x + y) mod n` so fields form rows.
- **Grass and parks (`grass` kind):** tufts at rest, grown from a soft value noise (`GRASS.lushScale`) plus a hash per cell (`grassCell`: dense, medium, thin, or sparse), whose same noise tints the cell: deep green above `shadeAbove`, straw below `dryBelow`, and a few straw specks in the margin. `windFront` sweeps fronts downwind (`WIND`: from the northeast, a front every 56 cells at 7 cells/s), bent by value noise and gated by slowly drifting noise patches, and returns the `gust` and the `wake` just behind its crest; above `GUST_STEPS` a blade leans downwind (`/`, `\`, or upright `|` when the wind runs along the columns), then lies flat. Most cells are in neither the front nor its wake, so `windFront` returns before the patch noise (two thirds of its hashing). The select pass gets `u_wind` = 0 with reduced motion and then skips the wind math altogether. The noise stays in integers until its last step, so world coordinates at z21 stay exact in the shader (`shaders/vegetation.ts`).
- **Woods (`canopy` kind):** a jittered crown center per 4 × 2 block of cells; the cell holding a center draws a crown glyph (by the wood's kind in the variant byte), cells around it foliage, and cells far from every center are clearings half the time (the gap dots are picked by the fixed world cell, so a moving clearing reveals them one by one). Foliage more than `CANOPY.lit` cells from its center toward the sun is lit, and away from it shaded.
- **Trees:** the worker draws a `natural=tree` point's crown (`tree_crown`, a render-only class that follows `tree`'s zoom band) as a lumpy 24-gon (`crownRing`: two sine lobes, a little jitter, and an oval stretch, scaled so its mean radius is half the `crown` diameter), seeded by a hash of the tree's id so the same tree has the same shape in every tile, and triangulated with earcut, since the lobes aren't convex; a crown every crown's width along a tree row, each seeded by its index too.
- **Trees in the wind:** trees read the grass's wind field `TREE_WIND.lag` (0.35 s) late (`treeFront`, `treeGust`). Crowns are kept out of the cell pass, in their own buffers (`TileGeometry.crowns`, each vertex's `ridge` its reach from the trunk). The cell pass draws everything else into base targets (`CellTargets.base` / `subBase`); the crown pass (`passes.ts crownPass`) blits the base into the live targets and draws the crowns over it. It runs after every cell pass and on every animated frame while crowns are on screen and the wind is on, so the per-frame cost is the base copy (`copyRaster`: up to four `blitFramebuffer` calls per grid, twice: the cell grid and the sub-cell grid) and the crowns' triangles, with each tile's matrix worked out once for both grids. In the cell vertex shader, each crown vertex swings downwind by the gust at its own cell times `SWAY.bend` × its reach in cells (at most `SWAY.max`), and springs back upwind of rest in the wake behind the gust (`SWAY.recoil`, rocking at `SWAY.bounce`), plus a flutter across the wind at its own phase (`gl_VertexID`). Where a crown swings away, the base shows the ground under it. Leaves flutter between `%` and `&` from `TREE_WIND.step` (`FLUTTER`); woods, which have no per-tree geometry, read their canopy pattern from up to `CANOPY.sway` cells upwind in a gust (a fractional offset: a whole shift plus a fraction, so the arithmetic stays exact in float32 and the clumps creep a cell at a time), so the clumps lean downwind and back. A flat crown draws a rim of `%` around an inside of `&` (with a dense `@` here and there), read from its neighbors in the class texture; its sunny side (toward `u_sun`, or the northwest at night) is lit and the far side shaded, and one crown in `CROWN.dryEvery` (by feature id) yellows. The wind level (`windLevel`, 0–3) and a tone (`Tone`: shade, light, dry) ride in the state byte, and the glyph pass lightens by `WIND_LIGHT[level]` and tints by `TONE`, relative to the class color so both themes work. `u_wind` = 0 (reduced motion) stills all of it, and the crown pass then runs only after cell passes.
- **The wind is live state** (`life/wind.ts`): `prevailingWind` picks the season's wind from the city pack's `climate` for the month (or the HUD's chosen strength, from the season's direction), and `windAt` veers it up to `WIND_VARIATION.veer` degrees and breathes its strength on slow noise. Each frame `index.ts` passes `{ dir, strength }` to the crown and select passes as `u_windDir` (a unit vector) and `u_wind` (0 with reduced motion). Fronts are laid out on world cells taken modulo `WIND.wrap` (4096), so float32 stays exact at z21. Fields (`crop` kind) and water gust bands read the same field.
- **Rain** (`RAIN`, `rainDrop`): with a storm, the glyph pass draws sparse streak cells falling `RAIN.speed` cells a second and drifting with the wind's x, in a glyph slanted by it (`theme.ts rainGlyphs`), over a slightly dimmed map. Rows are taken modulo `RAIN.wrap` first.
- **Shadows** (`SHADOW`, `inShadow`): the select pass looks up to `SHADOW.steps` cell widths toward the sun (`u_sun`: its direction and the tangent of its altitude, from `life/sun.ts solarPosition`, or `fixedSun` for the fixed day and dusk) for a building, tree, or crown standing taller than the sun rises over that distance, and sets `SHADOW_STATE` (8); the glyph pass darkens the cell by `SHADOW.dark`. The state byte: bits 0–1 hover/highlight/selected, 2 sub-cell edge, 3 shadow, 4–5 wind level (`WIND_SHIFT`), 6–7 tone (`TONE_SHIFT`).
- **Birds in trees:** the worker emits each tree point in a tile as a perch (`LifeGeometry.perches`, at most `MAX_TILE_PERCHES`). A flock picking where to go next flies to a tree with chance `PERCH.chance` and sits in it, still; `LifeWorld.step` takes a `gustAt(lng, lat)` (strength × `treeGust` on the grid's cells), and a gust over `PERCH.flush` flushes the flock, which scatters for `PERCH.scatter` seconds.
- **Labels** draw `labelText(name)`: NFKC (`Ⅱ` → `II`) and ASCII punctuation, so names fit the label atlas; search folds with NFKD for the same reason.
- **Terrain:** DEM luminance → `. : - = + * # %` ramp (Region level only).
- **Priority:** when several classes fall in one cell, a fixed priority order decides (label > landmark > road > building > water > tree crown > area > grass > terrain). Individual crowns and tree rows are an exception: the crown pass reads the cached base class and height at both resolutions, overriding depth over roads and over roofs/building parts lower than the crown. Equal-height roofs win, and overlapping crowns resolve by height. Heights are the existing rounded height bytes, including pipeline defaults. Road connectivity, curbs, and roof walls consult the base geometry beneath crowns so their outlines do not follow the leaves. Edge selection compares crown and roof heights; non-bird Life compositing checks the visible 2×3 surface samples so trunks, crowns, and woods conceal only covered agent pixels. Trunk point cells remain wholly opaque to non-bird Life; birds render above foliage. Occlusion changes drawing only, so simulation continues underneath. Woodland polygons retain their existing boundaries and priority.
- **Road strips (Place level):** from `ROAD_AREA_ZOOM`, carriageways are drawn as strips of their real width (built in the worker) instead of lines; road cells next to a non-road cell become curbs via the same wall mask, with "outside" meaning any class that is neither road nor see-through.
- **Roof surfaces:** detailed fill meshes optionally carry four Int16 values per vertex: local along/across meters, half ridge length and end scale. Each mesh carries a distance scale (normally 1/64 m per step, enlarged for long-range coordinates); end scale uses 1/32767 steps. Positive end scales that would round to zero, or scales outside the packed range, retain a Float32 fallback. This halves ordinary roof surface transfers from 16 to 8 bytes per fill vertex. Frames are computed once per building/leaf and written directly, with no unused ridge-distance work. Ground meshes allocate a zeroed typed ridge buffer directly; only crowns need temporary nonzero reach values. Mesh finalization preserves position clamping without per-element conversion callbacks. Crowns retain their separate two-component surface attribute. Gables have no end slope; hips shorten the ridge by half-width; pyramids use half-width / half-length for their hip angle. The cell pass encodes side, end, ridge and hip codes (0-7) in the existing alpha byte, and the select pass shades slopes against the physical sun vector. Existing ridge glyphs and the 10-bit atlas are reused. Versioned `roof_plan` partitions use one full-footprint Mercator origin; the worker triangulates the original polygon with holes, clips triangles through the bounded split tree, rounds shared intersections consistently, and preserves feature IDs and original Life footprints. Invalid plans fall back for the whole feature. Ordinary roofs still use tile-local bounds; rectangular roofs crossing tile edges remain a follow-up. Party walls resolve class before attributes/IDs and reuse their cached 3x3 samples for ordinary outlines. At compatible cardinal contacts, only the outer ring extends that cache to 5x5, which connects one western/northern-owned wall to exterior walls. No new render pass, class, flag or texture is needed.
- **Outlines (Place level):** from `OUTLINE_ZOOM`, a cell of an outlined feature is a wall if any of its 8 neighbors belongs to another feature (per `idTex`; paths, statues, and markers are looked through). A wall joins its neighbor in a direction when that neighbor is in the same feature and a cell touching both is outside, which draws corners and concave corners correctly without false junctions in thin buildings. The join mask indexes the single- or double-line wall set. Grounds (no height) are never outlined.
- **Sub-cell edges:** `subcellEdge` mirrors the select shader: only empty cells and areas take part (lines and markers win their cells whole); a building among the samples wins over the grounds, park, or water it stands in; walled features are left to their walls; a full or empty mask keeps the class glyph. The mask's bit `row × 2 + col` is the sample's sixth, from the top left, and indexes `sextantGlyphs`.
- **Classes by zoom:** each class has a zoom band in the shared `CLASS_ZOOM` table (e.g. `monument` from z17, terrain until 9.5); the cell pass crossfades it at the band's edges (see the Phase 2 notes above).
- **Labels:** place names (provinces, cities, subdivisions, smaller places, each with the band `featureZoomBand` gives it), curated landmarks (from z17), street names (tiered by road class and OSM `highway` kind in `streetLabel`: major roads from z14, secondary from z15.5, tertiary from z17.5, other streets from z18, paths from z18.5), and monuments (from z18) are placed greedily with selected and hovered names first, then rank, retained visible names, retained offscreen names, newcomers, and feature id, never overlapping, with a one-cell halo. New text fits the on-screen cells; accepted layouts may extend `KEEP_OVERHANG = 3` label cells beyond the fully visible cell bounds. Rounding means the margin from the physical edge is between two and three cells during a subcell pan. Rotated labels try their road-aligned slot first, then their remembered horizontal fallback and remaining beside slots; other labels try the remembered beside slot first. A global `15 ≤ zoom < 17` exclusion clears all glyphs, rotated street meshes, halos, collisions, and the visible-label list; normal bands apply outside it. Names beside an anchor go below, above, right, or left of it, wrapped at 18 characters. A street's name sits at the middle of its longest straight run, with glyphs rotated to that direction and normalized to an upright reading angle. Run endpoints determine whether the whole word fits; short runs, edge clipping and collisions fall back to horizontal beside placement. Rotated halo bounds reserve the collision grid and a dynamic vertex buffer batches the accepted glyph quads. Street names repeat at `STREET_REPEAT = 45` horizontal label-cell widths, using `hypot(dCol, dRow * labelAspect)`; other names occur once on screen. Repeat ownership is keyed by displayed text across kinds, with the incoming candidate's rank determining its distance limit: street candidates require that spacing from any same-text owner, while non-street candidates use infinity. Focus may reverse the order and therefore the suppression. Only accepted text intersecting the fractional physical viewport claims a repeat name; offscreen retained layouts still reserve collision space. Tile-copy selection prefers onscreen text over ghosts, then deeper source-tile geometry, then retains an eligible accepted copy, then chooses the longest eligible run with geographic tie-breaking. Detail arriving after a coarse copy replaces it when eligible; coarse copies remain a fallback when detail cannot qualify. Visibility uses the first geometrically admissible slot, including fallbacks when the remembered slot no longer fits. Entirely offscreen retained text stays in placement memory but leaves `labelschange`. The visible-label list stays in ordinary rank and feature-id order, independent of placement focus and memory. The event compares its complete payload so renamed labels and replaced anchors are reported even with unchanged feature ids. Collection prepares each tile copy once and retains the winning candidates for placement and focus. Eligibility uses the same numeric geometry as placement without constructing layouts; accepted layouts own their collision and text bounds. Whole-cell admission bounds come from the grid module, while physical visibility includes partial cells. Focus changes reuse prepared candidates and redraw only the overlay, reading but not committing the last cell draw's memory. Cell draws (including those during focus) commit memory. Label placement changes invalidate both hover and speech visibility evidence, including focus-only redraws. A separate snapshot of rendered IDs, slots and geometry detects unchanged focus layouts independently of placement order and durable memory; those layouts skip texture and street-buffer uploads and preserve visibility evidence. Unchanged focus/view/source inputs skip geometry work. The frame emits at most one final visible-label payload after shifting and relabeling; unchanged payloads avoid allocation and serialization. Context-loss clearing remains immediate; no extra cell/crown rasterization or class readback is requested. The ordinary crown animation schedule remains active.

## 5. Time model

- Every feature can carry:
  - `start_year?`, `end_year?`
  - `certainty?: 'exact' | 'circa'`
  - `name_history?: { name, from?, to? }[]`
- The pipeline writes these into tile feature properties.
- **Visibility.** In the cell pass, a uniform `u_year` is compared per feature, and invisible features are discarded. Visibility per feature is `start_year <= year && (end_year == null || year < end_year)`.
- **Transitions.** When the year changes, the previous and next visibility are both rendered. A per-cell mask (`scanOrder(x, y) < t`) decides which one shows, which produces the type-in and dissolve effects.
- **Names.** `name_history` is resolved on the CPU during label placement.
- **Underlays.** Imagery snapshots are pre-baked by the pipeline into grayscale raster tiles per year. The glyph pass samples the underlay luminance for cells with no feature class.

### Frame preparation and diagnostics

The Life worker pipelines simulation one accepted frame ahead of drawing. Agents may appear one frame late at a fast pan's leading edge, but remain registered to the current camera. Worker stages (`step`, `visible`, `clearanceBuild`, `clearanceChecks`, `sync`, `spawn`, `settle`, `terrainRebuild`, `terrainRoads`, `terrainRevalidate`, `terrainEncode`, `replyClone`) merge into the next main-thread sample; replies received between callbacks are retained. `sync` includes tile spawning/settlement and `terrainRebuild` isolates static terrain preparation and revalidation. Worker sync timing is retained until its next frame reply. `spawn` and `settle` split tile admission; `terrainRoads` and `terrainRevalidate` are nested inside terrain preparation. On the main thread, `syncPost` measures posting newly resident tile geometry to the worker (a synchronous structured clone), `terrainSnapshot` measures accepting a terrain reply, `tileUpload` measures GPU submission for arriving tiles (including reload after context restoration), and `lifeLatency` measures posting a frame through receiving it. `FrameProfiler.record` retains these between callbacks. Latency includes queueing and messaging, rather than just CPU time. Only with profiling enabled, `replyClone` measures an extra worker-side structured clone of agents/procession, an upper-bound proxy for reply deserialization that also includes serialization; it is outside step/visible timing. These stage times are worker CPU measurements and are not included in main-thread `draw` or `callback` CPU time. With the inline fallback, step and visibility timings are nested inside the main-thread draw as before.

Adaptive quality changes drawing only: Auto first thins drawn agents (1,200 → 700 → 500), then disables crown sway, ground wind, shadows, water detail, fish and beams, then caps DPR at 1.25. High pins the original drawing settings; Low pins the last tier. CSS-scheduled simulation clearance and gust coordinates remain independent of drawing DPR. Auto samples the next rAF callback after each draw, including callbacks that skip drawing; idle 30 fps pacing is not an overload signal. A bounded ten-second window requires 45 samples. Sustained p75 intervals above 25 ms for three seconds, or 40 ms for 1.5 seconds, lower quality after input has been quiet for one second. An eight-second cooldown and delayed, backed-off recovery trials prevent oscillation. Recovery requires healthy interval and CPU samples, changes no draw cadence, and does not require diagnostic profiling.

- Empty tile meshes have `count: 0`, a null VAO, and no buffers. Drawing and disposal skip them.
- Theme palettes are converted to RGB once per theme change. Vehicle part glyph indices belong to each map glyph atlas, rebuilt for theme, density, DPR, or context changes.
- Crown filtering and matrices are reused while tiles, meshes, zoom, DPR, cell dimensions, grid origin, and target dimensions stay the same. A shift inside a cell does not change a matrix.
- Label grids, collision storage, and packed upload buffers are reused per render target and reset before placing labels again. A separate `LabelMemory` map survives resets and is refilled with accepted slots and their last cell draw's physical text visibility only. Candidate caches and placement memory belong to each atlas/target. Target replacement with unchanged label dimensions and cell size transfers only durable acceptance and previous copy references, including across map-density steps; geometry and upload state are rebuilt. Incompatible label geometry, context loss and disposal release them. Maps do not share mutable buffers.
- `Atlas.setReducedMotion(enabled)` applies a system preference change immediately while preserving saved Life settings. It clears agents and moving lights, stills animated effects, finishes an active flight once at its destination, and resets the simulation step clock before resuming. The web app and HUD subscribe to the same media query.

- `Atlas.setFocus(focus: LegendFocus | null)` accepts copied map-class and Life-group descriptors. `LegendFocus` contains `classes: readonly RenderClass[]` and `life: readonly LifeFocus[]`; groups distinguish traffic, people, vendors, pets, boats, trains and birds even when they share a drawing class. Final merged legend entries carry optional descriptors, keyed in transient UI state by `LegendEntryId`. Equal normalized descriptors avoid redraws. Map membership uses two unsigned 32-bit uniform words (class zero excluded); active focus pulses unless reduced motion is requested. CPU focus survives context recovery, while atlas replacement clears UI focus. Panel hiding and legend collapse leave the mounted legend's subscriptions intact.
- `packLife` accepts one optional final metadata object containing a reusable `Uint32Array` of frame-local owners and a readonly focus-group set. Owners are original agent indices plus one, independent of parked-first packing; zero denotes empty/shadow cells. Full writes replace ownership, line writes block underlying tooltips, and rejected whole-agent journals restore four texture bytes plus the prior owner. Owners never become simulation identities or GPU textures. `lifePass` retains its numeric return and pairs its raster revision with the exact visible-agent array. Life B uses permission mask 79 (vehicle/person/boat/bird/train), focus bit 32, and indicator bit 128; alpha retains existing paint/part/shadow meanings.
- `lifehover` emits `{ label, point }` or `{ label: null, point: null }` in canvas CSS pixels. Candidate ownership and exhaustive simulated names are validated using the existing asynchronous readback queue: one three-read batch obtains the glyph class and pointed subcell class/height. Updates validate captured evidence against current geometry, identity, pointer subcell and candidate label; incomplete batches use the bounded cadence-aware expiry above and respect the queue's eight-read cap. No candidate means no visibility reads. Normal label cells and rotated label/halo quads suppress hover, including dissolved cells. Mouse position changes and stationary-pointer agent changes are evaluated once per frame. Exit/press, Life off, reduced motion, target recreation, unwatched canvas, context loss and disposal clear hover. The UI gives agent names precedence over landmark tooltips without changing picking or cursors.
- Focus halo sampling is bounded to eight neighboring cells and runs only with focus enabled. `u_focusLife` skips neighboring Life texture reads for map-only focus; the receiving pixel's surface and height are sampled once outside that loop. Agent ink and halo share one GLSL surface-permission/canopy predicate; halo receiving cells must also permit the agent. Foreground map ink, its background fill and Life ink focus independently, preventing road focus from colouring traffic or hidden agents from colouring roofs. The halo composes below ink, agents, fixtures, weather and labels. No halo sentinel, new render target, population change, worker payload or geographic data is introduced.
- Back/Forward cancels pending URL writes and restores camera, selection, year (including the default when absent), and the requested tour step paused. Even a step of the currently open tour is restored. History restoration stops old flights and tour holds and does not enqueue a new history write.

`getStats().frameMs` measures CPU submission time. `gpuFrameMs` is a separate, smoothed GPU elapsed measurement in milliseconds, or `null` when disabled, unsupported, awaiting results, or invalidated by a disjoint event. `AtlasOptions.gpuTiming` defaults to false; the web app enables it only when the initial URL requests `debug=1`. Timing uses asynchronous `EXT_disjoint_timer_query_webgl2` queries around rendering commands, sampled at most once per 250 ms with at most four outstanding queries. It waits for availability, discards disjoint results, resets on context loss, and never requests a redraw to collect a sample. The debug overlay labels these counters `cpu` and `gpu`; unavailable GPU timing reads `n/a`.

#### Earlier isolated prototypes

`pnpm perf:life` compares seeded simulation fixtures against a Git revision (`--baseline=<revision>`) or a source snapshot (`--baseline-file=<path>`). The harness checks exact visible outputs and mover states before timing, alternates five runs of each variant, and reports median and p95 CPU durations, source hashes, runtime, and the actual warmup and batch sizes.

The candidate prototype pools metadata, delays headings and appearances until selection, and uses a stable bounded heap above the 1,200 ordinary-agent cap; procession agents are separate. The following prototype reuses line/direction groups and scans lateral/width buckets in reverse progress order, retaining the exact strict overlap check and progress/index tie order. Both live under `packages/renderer/scripts/prototypes`; production simulation does not import them.

Fixtures cover 1/4/16/64 tiles with desktop and phone viewport bounds, an artificial repeated-coordinate crowd, and 16/120/600 mixed vehicles. The artificial crowd uses tile simulations directly so collision settling does not remove repeated-coordinate agents; its stepping deliberately excludes cross-tile collision handling. These measurements isolate placement and following costs. They do not establish browser FPS, GPU cost, or performance on a physical phone.

### Continuity review corrections

Replacement admission processes one due tile per accepted step with fair rotation and at most 32 attempts. Its complete-body guard includes overlapping coarse/fine owners in the tile neighborhood; distant populations are excluded. Hidden-by-density residents still reserve admission space. Seeds expire after eight active simulated seconds or sixteen failures, retry no sooner than 0.5 seconds later, and remain frozen while retired. `spawnMargin` computes two CSS cells in meters for both hosts and synchronization; only admission applies the 12 m minimum.

Private activation marks commerce complete only after the full generator finishes. Cancelling its tile set discards touched fresh instances and their terrain references, rebuilding from original seeds, while resident/retired instances are retained. Occupancy construction yields in bounded batches. Worker replies and inline rendering finish before scheduled preparation turns; those turns never activate or step Life. Ready state commits only at the next accepted frame. Consumed activation terrain cache entries are deleted without mutating already published snapshots.

Missing-owner seam waits expire after three active simulated seconds and then defer to existing route endpoint behavior, including one-way terminal holds. Existing but unsafe/full destinations still require successful admission. Destination replacement pools are grouped by kind once; nearest selection uses stable linear scans and membership Sets.

For real-data birth pressure, run `pnpm perf:world --pan --real=naga --births --baseline=12ff503 --runs=5 --scratch=<task-folder> --output=<task-folder>/births.json`. The case supplies the production view/margin context, shifts one column, then simulates 60 seconds; reports include pending births and admission guard builds. `--control` compares the current source against itself. Timings do not establish hardware frame rates.

`pnpm exec tsx packages/renderer/scripts/perf-continuity.ts --runs=5 --output=<task-folder>/preparation.json` measures real worker RPC loading against synchronous preparation of the same corrected populations. Simulation is frozen (`dt=0`) to compare identical activation batches and final population hashes; the report separates preparation CPU, slice p95, activation, reply latency and accepted-frame age. `--control` compares staged preparation with itself. This is a loading diagnostic, not a live-animation or hardware FPS acceptance test.
