# Architecture — ASCII Atlas

The engine is city-agnostic. Everything specific to a city lives in its city pack (`packages/content/cities/<slug>/`) or is derived from OSM by the pipeline. Examples below use Naga, the first city.

## 2. Renderer public API

```ts
// meta = the city's <city>.meta.json, emitted by the pipeline
const atlas = createAtlas(canvas, {
  tilesUrl: `/tiles/${city}.pmtiles`,      // e.g. /tiles/naga.pmtiles
  theme: 'dark',
  cells: DEFAULT_CELLS,   // map cell width by zoom (density.ts); labels: labelCell, 10×18
  bounds: meta.regionBounds,
  initialCamera: urlCamera ?? meta.defaultCamera,
  year: 2026,
  processions: processionRoutes,        // optional validated <city>.processions.json
  emergency: emergencyData,             // optional validated <city>.emergency.json
  cityLife: cityConfig.life,             // optional seasonal calendar and daily schedules
  life: { season: 'auto' },              // Today; a pack id previews that season
  lifeHoverPause: 'item', // optional; 'all' restores global Life inspection
  utilities: { derive: cityConfig.streets?.utilities?.derive === true }, // optional; omitted disables
  dialogue: cityPack.dialogue,          // optional validated native/translation catalog
  speech: true,                        // display preference, independent of simulation
  emoji: true,                         // display preference; independent of the observer
});

atlas.setCamera(partial, { animate?: boolean, duration?: number });
atlas.flyTo(target: Partial<CameraState>, { duration?: number });  // duration overrides 0.8–3 s
atlas.getCamera(): CameraState;
atlas.project(lngLat: readonly [number, number]): [number, number]; // current canvas CSS pixels, before the first frame too
atlas.setYear(year: number, { animate?: boolean });
atlas.setEmergency(data?: EmergencyData); // late installation/replacement; undefined removes emergencies
atlas.setTheme('dark' | 'light');
atlas.setSpeech(enabled: boolean);
atlas.setEmoji(enabled: boolean);
atlas.getLabelObstacles(): readonly { left: number; top: number; width: number; height: number }[];
atlas.setSelected(featureId | null);
atlas.setFocus(focus: LegendFocus | null);            // transient map-class/Life-group/folklore focus
atlas.setHighlighted(featureIds: string[]);          // at most 64, e.g. a street's ways
atlas.getFeature(featureId): FeatureInfo | undefined; // once a tile with it has loaded
atlas.setLife(partial: Partial<LifeSettings>);        // includes season selection
atlas.setProcessions(routes: readonly ProcessionRoute[]): void; // optional routes arriving after startup
atlas.playProcession(id: string): boolean;            // play an event; false for an unknown id or inactive Life
atlas.stopProcession(): void;                         // stop playback; live events may resume
atlas.getSeason(): SeasonState | null;               // immutable resolved calendar snapshot
atlas.getStats(): AtlasStats;                         // fps, frame and cell-pass ms, tiles, decode ms
atlas.setUnderlay(null | { kind: 'imagery' | 'historic-map', id: string });
atlas.on('camerachange' | 'hover' | 'lifehover' | 'click' | 'flyend' | 'input'
  | 'procession' | 'classeschange' | 'labelschange' | 'fixtureschange' | 'seasonchange' | 'speechchange' | 'emojichange' | 'folklorechange' | 'contextlost' | 'contextrestored', handler);
atlas.destroy();
```

`classeschange` sends the classes drawn in at least one on-screen cell (for the legend), and `labelschange` the places, landmarks, and monuments whose names are on screen (`{ featureId, name, kind, lngLat }`, for the "Places in view" list); both fire only on change. `contextlost` and `contextrestored` bracket a lost WebGL context (see §3). `input` fires when the visitor moves the camera (drag, wheel, pinch, or keys; not clicks or hover), which also ends any flight; a tour pauses on it. `hover` and `click` carry `{ featureId, feature, point }` (`click` also `lngLat`), where `feature` is the slim `FeatureInfo` the tile worker recorded: class, name, subdivision (and whether it is approximate), landmark id, kind, and height. The package also exports `legendEntries(theme, zoom, present?)` and `CLASS_LABELS` for the legend.

Seasonal decoration uses `AtlasOptions.cityLife.seasons` and optional `LifeSettings.season` (default `auto`). Shared `runtimeCityLife` expands one-level `includes` references once: own decoration groups take precedence, missing groups use the first included value, and installations append in include order. Stable runtime objects preserve identity-based fixture caches; tile records retain their authoring season id. Installation admission accepts the selected season and explicitly included seasons. Dense bunting accepts only the selected group's author (`buntingSeasonId`): the season's own group, otherwise the first included group supplying bunting. The trimmed simulation table carries the same includes, stall settings and physical installation identities. `getSeason()` returns a stable, immutable `{id,title,labels}` snapshot or null; `seasonchange` fires only on selection changes. Real city date resolution runs initially and with sun/clock updates, independently of fixed time and historical year. Selection invalidates fixture inputs and stale Life agents; a valid terrain snapshot in an in-flight reply is still accepted. Hard clears, disposal and worker failures invalidate the entire reply. This preserves terrain guards without moving the camera or resetting ordinary populations.

Metadata loads independently of optional event geography. `setProcessions` installs later routes in place through either Life host, refreshes worker/main-thread permission caches, and invalidates stale replies without recreating the map or resetting ordinary tile populations. Replacement stops active event playback.

The web app owns app state (Zustand) and pushes it into the renderer. The renderer emits events back. The renderer never reads the URL or the DOM outside its canvas, and it knows nothing about specific cities. Switching cities destroys the atlas and creates a new one with the other city's tiles and meta.

`AtlasOptions.utilities?: { derive: boolean }` controls static overhead hardware independently of Life. `fixtureschange` reports `{ streetlights: boolean, trafficSignals: boolean, pedestrianSignals?: boolean, utilities: boolean }` when viewport-packed hardware changes; `utilities` indicates nontransparent packed marks, before the shader's surface mask. `pedestrianSignals` is present when pedestrian lens marks are visible and drives the independent `info:pedestrian-signals` legend entry; it is omitted when none are visible. `legendEntries` accepts that fixture report, including an omitted `utilities` field for older callers. Utility record version 1 is unchanged: pipeline validation remains strict, while the worker skips malformed or unsupported individual records using a Zod-free shape validator, retaining ordinary tile geometry.

**City meta** (`<city>.meta.json`, generated): `slug`, `name`, `subdivisionLabel`, `languages`, `bounds` (the city boundary bbox), `regionBounds`, `defaultCamera` (centered on the city config's `focus` feature at its zoom, else the boundary centroid), `yearRange` (earliest year with data to the current year), and `attribution` (map source credits, with one standalone OSM credit).

**Detail layouts** (`<city>.detail-layouts.json`, generated): detail ids mapped to SHA-256 geometry/selection fingerprints bound to the successful step 04 merge. Only smoke tests load this separately validated asset; the map does not fetch it at startup.

Undas-style memorial groups extend Life geometry through optional `graves` (Float32 x/y/exact 24-bit seed triples), `cemeteries` (x/y/radius triples), `cemeteryAreas` (feature identity, decoded rings/holes and tile-local burial presence) and `placeLandmarks` (accepted place ordinal and curated identity). Only numeric buffers transfer; polygon/string sidecars use structured cloning. Graves and cemetery fallback polygons are admitted only at archive maximum zoom, with half-open ownership and world-quantized marker identities. Grave decoding hashes each feature once and retains numeric world-coordinate identity keys separately from compact seeds. For packs with candles or visitors, the tile worker prepares bounded safe `memorialSites` (Float32 x/y/seed triples) with aligned `memorialFragments` identities before transfer; computed-empty arrays prevent repeat terrain indexing. Both fixture and simulation consumers retain this data for later previews. Cemetery proximity centres and accepted worship identities remain available at other Life zooms. `PLACE_STRIDE` and ordinary place kinds remain unchanged.

Seasonal visitors and congregations use dedicated persistent RNG streams for admission, appearance, targets, pauses and retries. Visitors use the same bounded memorial anchors as candles. Complete families precede congregation candidates, and active plus suppressed owners share `MAX_TILE_GATHERERS`. Separate crowd application tokens retain equivalent seasonal carts and prevent repeat admission. Calendar changes clear live/suppressed crowds and their inspection references; eviction clears crowds before retirement, and activation reconciles prepared or revived tiles against the current calendar. Seasonal activity shares control rendering, ground/pedestrian occupancy and bird disturbance; these owners do not enter legacy moment or speech candidate budgets. The separate candle glyph is appended after every existing atlas entry, uses a candle-only burial-surface exception, and supplies headless compact pools only at z18 and above.

## 3. Rendering pipeline (per frame)

Pack-defined `life.seasons[].fireworks` supplies a label and a validated subset of `peony`, `chrysanthemum`, `ring` and `willow`. A lazy instanced pass after glyph drawing and before street text reuses the map atlas and one immutable buffer capped at 50 shells / 8,600 particle quads (137,600 bytes). The tile worker extracts one interior triangle-centroid anchor per mapped residential building fragment from its existing OSM kind and triangulated footprint. Concavities and holes are respected; buffered anchors outside the owning tile are dropped. These small render-only records remain outside Life. The main thread compiles loaded residential sites only when the drawn tile set changes, preferring deeper copies and deduplicating by feature identity. A per-context seeded generator uniformly selects an eligible, unoccupied home within each slot's ground search bounds, then samples height, visual seed and an independent pause after the previous smoke expires. Small untyped roofs (20 to 450 square metres of footprint) also qualify within 35 m of a street explicitly tagged residential or living street when at least two other eligible roofs lie within 60 m. A worker-local spatial bin index checks these neighbors once at decode, not per frame. Known nonresidential kinds, curated untyped landmarks, isolated untyped roofs and service/unclassified roads do not qualify. These conservative thresholds are illustrative neighborhood inference, not a verified occupancy survey. There is no fallback over fields or water; insufficient coverage reduces the display. Missing sites retry at most twice per second per slot, immediately on changed geography, or on camera movement in reduced motion. Hidden regular slots search wider footprints according to their density rank (the inverse quadratic admission curve), centered on the current camera. This retains broad distant coverage after entering or staying in a close view without moving active launches. Regular heights are 80–220 illustrative units; the extra distant high slot is 460–560. Rise time is `0.55 + height * 0.005` seconds; sparks/smoke last 4.4/4.8 seconds, followed by a 0.25–3-second pause. Full initial intervals are sampled to prevent synchronized entry waves and lulls. The atmospheric eye height is `320 / 2 ** (zoom - 19)`; it descends from 320 at z19 to 80 at z21. A launch is visible only while its height is below the eye. Centers use ordinary ground projection to stay above their residential footprints; extents use the altitude factor `eye / max(eye - height, height * 0.15)`. Radius is the larger of `(30 + height * 0.1) * 2 ** ((zoom - 16) * 0.5)` CSS pixels and projected `height * 0.35` extent, capped at 520 CSS pixels. The distant legibility extent grows with every closer fractional zoom instead of remaining flat. Fixed visible launches never shrink on approach. A smooth altitude opacity fades them over the final 35% of their height separation, reaching zero when the eye passes below the burst. Higher breaks disappear before lower ones; there is no z16 high-slot cutoff or substitution of lower launch heights. Spark ink width is `min(12, 2 + sqrt(radius) * 0.6)` CSS pixels, independent of map-cell detail. Aerial glyph centers are no longer snapped to the ground grid; atlas lookup and label halos still use the existing cells. Ascent, sparks and smoke share packed altitude opacity. The pool of up to 49 regular launches remains cached, but the regular admission ceiling falls quadratically from 49 at z16 to four at z20, then linearly to zero at z21 (rounded up). Including the extra high slot while below the eye, total ceilings are 50/31/17/7/4 at z16/17/18/19/20 and two at z20.5. Selection prioritizes previously admitted, still-visible regular launch identities before nearer replacements, reducing by proximity within that group when the density ceiling falls. The high launch is separately reserved until its altitude cutoff; a culled high slot does not admit an extra regular launch. Heights and clocks remain unchanged. At z21 ambient packing and the legend entry are skipped; active requested Life shells can still use the pass. Packed center/seed/radius, age/rise, visibility/ink width and source indices are reused in fixed arrays; selection swaps all fields together without frame allocations. Two instanced draws submit only admitted smoke and spark prefixes, with smoke under tails/tips (at most 688 particles at z20). Vertex shaders handle ascent, expansion, tails, fade and wind; expired particles collapse to off-screen degenerate quads. There are no per-frame vertex/texture uploads, new glyphs, geographic archive records or Life-worker data. Place-label halos stay readable. The effect is independent of Life, selected hour and wind strength; reduced motion freezes poses, disables drift and reframes only after a complete pan away. GPU resources follow normal destruction/context recovery; inactive packs and hidden zoom levels allocate nothing. The sky projection is illustrative and does not change the north-up map camera or represent calibrated physical metres.

Residential extraction requires both the pack's fireworks capability and an active fireworks season. Worker control messages update the active flag as selection changes; detailed drawable tiles loaded while inactive request missing sites on activation. Computed-empty buffers are cached separately from uncomputed sites. Street segments are indexed in their occupied 35 m cells before exact distance checks. Sites cross the worker boundary as transferred `Float64Array` triples (`feature index`, `tile x`, `tile y`); the sampler compiles only for an active fireworks season and uses spatial bins for uniform eligible-site queries. Below z12, cold views request at most sixteen geographically distributed z12 residential tiles (clamped to the archive zoom range), including the camera center. These requests share the existing queue below drawable-tile priority and retain at most 32 site buffers without GPU meshes; detailed responses also attach to their loaded tiles. Packs without fireworks skip extraction, and leaving the season cancels queued coverage requests. In-flight supplemental requests finish their real extraction so a late reply cannot cache an artificial empty result. Active launch centers stay fixed while coverage changes.

1. **Camera → visible tiles.**
   - Compute the view frustum in mercator space.
   - Select tiles at `floor(zoom)` for the view, plus a 1-tile margin.
   - Use overzoom for zoom levels above the max tile zoom (z16 recommended).
2. **Tile decode (worker).**
   - Fetch via `pmtiles` range requests, then decode with `@mapbox/vector-tile`.
   - Convert to typed arrays per layer (triangulate polygons with earcut, keep lines as polylines).
   - Runs in a Web Worker; results are cached in an LRU by tile key.
3. **Cell pass (GPU).**
   - Render geometry into an offscreen framebuffer whose resolution equals the cell grid (e.g. 384×108 for a 1920×972 canvas at 5×9).
   - Uses MRT (multiple render targets):
     - `classTex` (RGBA8, red only: feature class id; RGBA so the legend's readback needs no conversion)
     - `attrTex` (RGBA8: height, shade, time-visibility, flags)
     - `idTex` (RGBA8: 32-bit feature id packed)
   - Lines are drawn with width in cell units so roads stay 1 cell wide at every zoom.
4. **Neighborhood pass.**
   - A fragment shader samples each cell's 3×3 neighbors in `classTex` to get road connectivity bits (N/E/S/W and diagonals).
   - The bits index a lookup table of box-drawing glyphs.
5. **Glyph pass.**
   - Full-resolution draw of one instanced quad per cell.
   - Each quad samples the glyph atlas (a canvas-generated monospace font texture, SDF optional) at the chosen glyph and colors it from the theme.
   - Time and animation effects (water shimmer, type-in/dissolve masks, selection glow) are applied here.
6. **Labels.**
   - CPU placement on the cell grid with greedy collision placement: selected, hovered, then rank, retained visible names, retained offscreen names, newcomers, and feature id. Rotated streets try their road-aligned slot first; typed remembered horizontal slots precede the other horizontal fallbacks.
   - Per-target memory retains accepted slots through pans; only retained layouts get a three-cell margin beyond the fully visible cell bounds. Tile copies are filtered for eligibility before consolidation: onscreen text, deeper source-tile geometry, an eligible accepted copy, then longest run and geographic ties. Focus-only frames rebuild the overlay without rasterizing cells or adding a crown frame.
   - Place labels use the glyph overlay. Street labels use a batched glyph-quad pass over it, rotating whole words in screen pixels with the same atlas, theme, halo and deterministic dissolve. Their conservative rotated bounds participate in the same collision grid; short straight runs fall back to beside placement.
7. **Picking.**
   - On hover or click, read back a single texel from `idTex` at the pointer cell, asynchronously (`readback.ts`, see the notes below). A feature that fails the `interactive` option (the web app passes "is a landmark with facts in its city pack") counts as a miss: it is neither highlighted nor reported.

Rasterization runs only when the camera, year, or tiles change. While watched, animation redraws the crown, Life, lighting, select and glyph passes at 30 fps when idle and at 60 fps for 500 ms after input (`pacing.ts`). A frame is due 4 ms early (`PACING_SLACK_MS`): rAF timestamps jitter around the display period, and an exact 33.3 ms interval skipped alternate 60 Hz ticks (idle ran at 33/50 ms, about 23 fps). Camera-driven redraws (input, `setCamera`, flights) keep the same 60 fps cap: every frame at 60 Hz, every second one at 120 and 144 Hz. Pacing keeps to a phase anchor (`nextAnchor`): a late frame keeps the ideal phase, so 90 and 100 Hz displays alternate one and two ticks (about 60–67 fps) instead of halving to 45–50, and an early frame restarts the phase. A camera move on a skipped frame stays pending, and the next due frame draws the latest camera. Discrete changes (selection, focus, theme, settings), resizes and context restoration draw at once. Picking, Life hover and cue geometry and taps use the camera and size of the last completed draw, so a pending camera never pairs with an older raster. Reduced motion or an unwatched map pauses autonomous animation; their dirty views still redraw immediately.

**Pan margin.** The map and label targets cover the viewport, the select pass's one-cell neighborhood and a margin of 1/8 of the viewport per side (`grid.ts` `PAN_MARGIN`, `windowCells`). Each drawn window freezes its origin, projection (`toCell`, tile matrices, `world`) and size; `Grid.shiftX/shiftY` is the screen's offset inside it. A pan that keeps the screen and its neighborhood inside both windows (`gridContains`) at the same zoom, DPR and cell sizes only moves the offset (`shiftGrid`): no cell pass, label projection, Life geometry or fixture/lamp repacking. Any fractional zoom change, a tile arrival, settings, resize or leaving the margin places and draws the windows again. Tiles are requested for the whole drawn window; Life membership still follows the physical view. The host and the Life worker keep the geometry of the 64 most recently synchronized tiles beyond the current set (`life/recent-keys.ts`, the same rule on both sides), so a tile returning to the view is synchronized by identity rather than cloned again. Fixture repacking first drops streetlights and utility poles/spans more than 60 m beyond the drawn window (`cullFixtures`); signals, flagpoles and seasonal decorations stay. `tileCache.tilesToDraw(…, false)` resolves the view's Life membership without changing what is wanted, and an in-margin pan synchronizes Life only when that membership changes, or at most every 100 ms for preparation focus, plus once more 150 ms after the camera stops, through the existing identity-only payload; Life's bounds travel with every frame request. `screenArea` stays the physical viewport: visible classes, label admission, obstacles, fixture visibility and accessible reporting never count the margin. Whole cells entering or leaving the screen mark visible classes stale, re-admit labels from geometry cached for the frozen window (`AtlasLabels.readmit`; collection projects each label once per window), and recompute fixture visibility from per-cell sight bits recorded while packing (`FixtureSight`). Every screen-to-cell mapping goes through `cellAt` (picking, Life hover, taps, cue label guards), the inverse of the glyph pass's `(screen + shift) / cell`. The select pass is scissored to the visible cells plus one more each side. Crowd admission, its cap and figure clipping use the pre-margin core cells (`coreCells`), so margin cells never displace figures on screen.

**Zoom throttle.** Every drawn fractional zoom rasterizes and reprojects agents, fixtures, lamps and labels. Side work for unchanged tiles (Life membership/focus sync, firework sites) runs at most every 100 ms during a continuous zoom and once more 150 ms after it stops; changed window or Life tiles, tile arrivals, season, settings and lifecycle invalidations run it at once. Lamp inputs keep their arrays while the window's loaded tiles stay the same.

The glyph program compiles inactive legend-focus and candle-clock features away. It starts with the minimal variant, so normal maps avoid the inactive halo loop and clock sampler. With `KHR_parallel_shader_compile`, idle tasks prewarm variants from the first drawn frame on, input or not, starting at most one link per rendered frame and finishing only links whose completion query succeeds; without it, warmup compiles synchronously only after one second without camera/pointer input. The focus variant warms first; clock combinations warm only when the existing Life packing scan finds candle actors. This avoids compiling unused clock shaders on ordinary maps without adding an agent scan. The pending warmup can upgrade when candles arrive, and compilation remains serial. With `KHR_parallel_shader_compile`, completion is polled before link status and uniform introspection; otherwise at most one variant compiles per idle turn. A frame that needs a variant before its link completes finishes it through the normal synchronous path, so a cold first demand can still hitch; those waits are profiled as `shaderWait` (quiet synchronous warmup compiles are not). Pending links and scheduled tasks are cancelled on context loss and disposal. Each variant is compiled once per context and released with the other programs; context restoration starts a fresh cache. Switching focus or clock-texture availability selects the matching program without changing compositing or simulation behavior.

**Hover and legend focus hardening.** `LegendEntry.id` and the exported `LegendEntryId` identify entries independently of their labels: canonical `class:` identities preserve explicit marker/building and crown/trunk grouping, `life:` identifies simulated groups, and `info:` identifies explanatory entries. Legend merging, transient selection, React keys, synthetic Life descriptors and local subdivision wording use those IDs. The always-mounted HUD resolves its list and clear control from one current entry and refreshes the renderer descriptor as class membership changes. Measured header clearance is published as CSS properties for legend scrolling and expanded mobile sheets, following the attribution-height pattern. Tooltips measure on label/element-size changes and use a pure placement helper for pointer/visible-viewport changes. Hover candidate keys include packed class and masked agent permission bits, excluding cosmetic flags. Pending batches, confirmed visibility and held inspection share a request-age limit: `min(1000, max(250, 4 * recentFrameIntervalMs))`, using the maximum of the last four active hover-update intervals. This permits a two-frame read and its renewal on slow devices while bounding stale evidence under saturated queues. Lifecycle invalidation resets cadence and rejects old callbacks. No hover-frame geometry or label callback is constructed without a pointer.

**Life inspection pause.** `AtlasOptions.lifeHoverPause?: 'item' | 'all'` defaults to per-item inspection. Worker and inline worlds assign stable actor IDs independent of raster indices and optional profiling identities. A static, non-enumerable symbol slot on each simulator owner holds a typed record fenced by registry and reset epoch, keeping object shapes stable across worlds. A weak fallback handles the rare owner shared by separate registries. Visible views carry numeric IDs across the worker boundary without owner-record references. A bounded latest-visible lookup accepts a desired ID and monotonically increasing command revision before stepping. Reused numeric admission stamps compact capped lookup entries in place; unseen or capped selected owners are released. Replies carry no unused inspection acknowledgement. Host generations reject old world replies and identities. Held movers retain collision and junction occupancy while skipping movement, gait and local scene timers. Shared traffic signals, fish, weather and other actors continue. Logical groups share one identity, including the pagoda, all rope-connected towing columns and their crews. Independent escort boats and crowds keep separate identities. Birds retain stable IDs; neither inspection mode pauses them. Their mouse tooltip appears while visibility is confirmed in the pointed cell and clears when they leave it. Actor clock/progress offsets prevent catch-up; live procession offsets survive replay controls and reset for a new real occurrence.

The hover controller selects an actor only after asynchronous surface verification. It renews both positive and negative evidence from 125 ms using generation, actor, geometry and subcell keys, independently of unrelated raster revision changes. Callbacks record only captured request evidence; the next update validates it against current owners and agents, even when raster buffers were repacked in place. Moving within the same held item preserves its tooltip while a new subcell is verified, without extending evidence age. Hover and speech share the surface predicate and three-read helper and reserve two slots in the eight-read queue. The existing bounded cadence-aware evidence expiry still applies. Camera/input, geometry, settings and visibility/context invalidations clear inspection. Unchanged accepted worker frames retain raster owners, draw count and revision without repacking or uploading until their paired frame, target, placement, camera/density, theme, sun or focus changes.

Carried candles use a lazy, nearest-sampled `RG32F` texture: R identifies the ink clock and G the winning candle-pool clock. Tokens use `ORDINARY_CLOCK` (`-1`) for ordinary time, nonnegative values for accumulated pause offsets, and `heldClock(time)` (`HELD_CLOCK_BASE - time`, with base `-2`) for held time. Packing and GLSL share these definitions from `life/effect-clocks.ts`. Only candle shader paths sample it. Life packing records only clocked candle writes and resolves their final raster owners. Ink/R and lighting/pool/G writers track previous and current token cells independently, so an idle lighting pass keeps its pool channel. Winning pools replace tokens, including ordinary-time winners. A separate content revision suppresses unchanged uploads despite unrelated raster revisions; ink clocks update even in daylight. Lamps, traffic signals and environmental effects retain their shared clocks. The texture adds no render pass and is released when no clock tokens remain, when targets resize, on context replacement and on disposal. Identity metadata remains on the CPU; no GPU ownership texture is added.

**Life taps.** The input callback captures geographic and drawn-frame evidence before the unchanged landmark picker call. **Implementation notes (Phase 1).**

- Steps 4 and 5 are split differently: a cell-resolution *select pass* does the neighborhood lookup and all glyph selection, writing one glyph index and class per cell, and the glyph pass is a single full-screen triangle that reads that texture. It gives the same result as instanced quads with less work.
- Class priority is the cell pass's depth value, in tiers; within the building tier, taller features win, so height-less grounds (e.g. a school campus) sit under their buildings.
- The cell grid is anchored to the world, and the glyph pass shifts it by the pan offset inside its frozen window, so panning scrolls smoothly instead of re-quantizing.
- Zoom follows the 512-px tile convention (`@math.gl/web-mercator`, MapLibre).

**Implementation notes (Phase 2).**
- **Crossfades.** Each frame the cell pass gets every class's visibility (`bandVisibility` of its `CLASS_ZOOM` band, 0–1). A partly visible class keeps only the cells whose per-world-cell hash falls under its visibility and discards the rest, so it dissolves into the layer beneath and the dither stays put while panning.
- **Region layers.** The sea, coastline, terrain, and admin boundaries are ordinary classes: terrain bands nest, and the band number in the height byte makes the higher band win (the `ramp` glyph kind picks `. : - = + * # %` from it). Admin lines are see-through for outlines and curbs.
- **Picking.** The pointer maps to a cell by inverting the glyph pass (`picking.ts`). After a frame is drawn, one texel of `idTex` is read, at most once per frame, without blocking: `readback.ts` issues `readPixels` into a pixel-pack buffer with a fence, and copies the data out a frame or two later, once the fence has signaled. A read from render targets that were recreated in between (a resize) is dropped. The tile worker sends a `FeatureInfo` for each feature it registers, so an index resolves to a feature without keeping tiles on the main thread.
- **Selection.** The select pass compares each cell's feature index with the hovered, selected, and highlighted indices and writes a state into the glyph texture's spare channel; the glyph pass brightens hover and draws the accent color (with a shimmer for the selection, unless reduced motion is on).
- **Fly-to.** Flights follow van Wijk and Nuij's zoom-and-pan path (as MapLibre's `flyTo`), eased, 0.8–3 s (≤0.3 s with reduced motion). Any input cancels one.
- **Zoom-out limit.** On every resize, the minimum zoom becomes the zoom that fits `regionBounds` in the view, and the view keeps the whole screen over the region.

**Implementation notes (post–Phase 2 hardening).**
- **Legend of what is on screen.** After a cell pass (at most every 250 ms, and always after the last one), the on-screen part of `classTex` is read back the same asynchronous way, and the set of class ids present is sent as `classeschange`. `legendEntries` drops a zoom-visible class that the cell pass draws but that isn't present.
- **Labels fade.** Labels use the classes' fade (`bandVisibility`, half a level at each band edge). A partly visible label keeps its whole box for collision, but only the share of its cells (text and halo) whose hash of (label, cell) falls under its visibility, so it dissolves like a class and the pattern holds while panning.
- **Lines claim their vertices' cells.** GL_LINES skips a segment that never leaves one cell's center diamond, so a river of many short segments broke into dashes at the City level. The tile worker also emits a point at every line vertex, which always covers its cell.
- **Lost context.** On `webglcontextlost` the renderer calls `preventDefault()`, stops its loop, and forgets every GPU handle without deleting it (the tile cache drops its meshes, and tiles that arrive meanwhile). On `webglcontextrestored` it recompiles the programs, rebuilds the glyph atlas and render targets, and asks for the view's tiles again; feature indices survive, since the worker keeps its id registry.

**Implementation notes (legibility: two colors per cell, sub-cell edges).**
- **Fill.** The select pass writes a fourth byte, the class whose fill is the cell's background (`fillClass`: the cell's own class, except carriageways drawn as 1-cell lines). The glyph pass mixes the background toward that class's color by its `fill` strength (`GlyphTables.fills`), then draws the glyph over it. Agents are drawn over the same fill.
- **Sub-cell targets.** The cell pass runs its ground draw a second time into class, attribute, and id targets at `SUB` (2 × 3) samples per cell (`CellTargets.sub`). The crossfade hash divides the fragment position by the sample count, so both resolutions keep the same cells.
- **Edges.** For an empty cell or an area cell (`subcellClasses`) that isn't walled, the select pass picks the foreground feature (the cell's own area, or a building among the samples), builds a 6-bit mask of the samples whose id matches it, and on a partial mask emits that sextant (two glyph-table rows, `SEXTANT_ROW`) with `EDGE_STATE` set in the state byte and the first other sample's class as the fill. The glyph pass draws an edge's ink between the feature's fill and its color (`EDGE_INK`).

## 4. Glyph selection rules

The rules live in `glyphs/select.ts` and mirror the shader logic, so they can be unit-tested on the CPU.

- **Water:** short crests of the second glyph drift east along each row, with rows offset and moving at one of two speeds and some crests skipped; reduced motion holds the pattern still. Rivers and streams (styles with the six stroke glyphs) draw a 1-cell-wide run that isn't horizontal as a stroke instead: `(` and `)` alternating down a vertical run, `╱` / `╲` for a diagonal one, judged from which neighbors are any water class.
- **Buildings:** luminance from shade × height factor maps onto the `░▒▓█` ramp.
- **Roads:** connectivity bitmask → box-drawing LUT. Road hierarchy picks a single-line or double-line set.
- **Area fills** (farmland, parking, pitches): patterned by `(x + y) mod n` so fields form rows.
- **Grass and parks (`grass` kind):** tufts at rest, grown from a soft value noise (`GRASS.lushScale`) plus a hash per cell (`grassCell`: dense, medium, thin, or sparse), whose same noise tints the cell: deep green above `shadeAbove`, straw below `dryBelow`, and a few straw specks in the margin. `windFront` sweeps fronts downwind (`WIND`: from the northeast, a front every 56 cells at 7 cells/s), bent by value noise and gated by slowly drifting noise patches, and returns the `gust` and the `wake` just behind its crest; above `GUST_STEPS` a blade leans downwind (`/`, `\`, or upright `|` when the wind runs along the columns), then lies flat. Most cells are in neither the front nor its wake, so `windFront` returns before the patch noise (two thirds of its hashing). The select pass gets `u_wind` = 0 with reduced motion and then skips the wind math altogether. The noise stays in integers until its last step, so world coordinates at z21 stay exact in the shader (`shaders/vegetation.ts`).
- **Woods (`canopy` kind):** a jittered crown center per 4 × 2 block of cells; the cell holding a center draws a crown glyph (by the wood's kind in the variant byte), cells around it foliage, and cells far from every center are clearings half the time (the gap dots are picked by the fixed world cell, so a moving clearing reveals them one by one). Foliage more than `CANOPY.lit` cells from its center toward the sun is lit, and away from it shaded.
- **Trees:** the worker draws a `natural=tree` point's crown (`tree_crown`, a render-only class that follows `tree`'s zoom band) as a lumpy 24-gon (`crownRing`: two sine lobes, a little jitter, and an oval stretch, scaled so its mean radius is half the `crown` diameter), seeded by a hash of the tree's id so the same tree has the same shape in every tile, and triangulated with earcut, since the lobes aren't convex; a crown every crown's width along a tree row, each seeded by its index too.
- **Trees in the wind:** trees read the grass's wind field `TREE_WIND.lag` (0.35 s) late (`treeFront`, `treeGust`). Crowns are kept out of the cell pass, in their own buffers (`TileGeometry.crowns`, each vertex's `ridge` its reach from the trunk). The cell pass draws everything else into base targets (`CellTargets.base` / `subBase`); the crown pass (`passes.ts crownPass`) blits the base into the live targets and draws the crowns over it. It runs after every cell pass and on every animated frame while crowns are on screen and the wind is on, so the per-frame cost is the base copy (`copyRaster`: up to four `blitFramebuffer` calls per grid, twice: the cell grid and the sub-cell grid) and the crowns' triangles, with each tile's matrix worked out once for both grids. In the cell vertex shader, each crown vertex swings downwind by the gust at its own cell times `SWAY.bend` × its reach in cells (at most `SWAY.max`), and springs back upwind of rest in the wake behind the gust (`SWAY.recoil`, rocking at `SWAY.bounce`), plus a flutter across the wind at its own phase (`gl_VertexID`). Where a crown swings away, the base shows the ground under it. Leaves flutter between `%` and `&` from `TREE_WIND.step` (`FLUTTER`); woods, which have no per-tree geometry, read their canopy pattern from up to `CANOPY.sway` cells upwind in a gust (a fractional offset: a whole shift plus a fraction, so the arithmetic stays exact in float32 and the clumps creep a cell at a time), so the clumps lean downwind and back. A flat crown draws a rim of `%` around an inside of `&` (with a dense `@` here and there), read from its neighbors in the class texture; its sunny side (toward `u_sun`, or the northwest at night) is lit and the far side shaded, and one crown in `CROWN.dryEvery` (by feature id) yellows. The wind level (`windLevel`, 0–3) and a tone (`Tone`: shade, light, dry) ride in the state byte, and the glyph pass lightens by `WIND_LIGHT[level]` and tints by `TONE`, relative to the class color so both themes work. `u_wind` = 0 (reduced motion) stills all of it, and the crown pass then runs only after cell passes.
- **The wind is live state** (`life/wind.ts`): `prevailingWind` picks the season's wind from the city pack's `climate` for the month (or the HUD's chosen strength, from the season's direction), and `windAt` veers it up to `WIND_VARIATION.veer` degrees and breathes its strength on slow noise. Each frame `index.ts` passes `{ dir, strength }` to the crown and select passes as `u_windDir` (a unit vector) and `u_wind` (0 with reduced motion). Fronts are laid out on world cells taken modulo `WIND.wrap` (4096), so float32 stays exact at z21. Fields (`crop` kind) and water gust bands read the same field.
- **Cloud shadows** (`life/sky.ts`): slow independently seeded cover uses the shown sun moment and a rounded bounds-midpoint location seed. The unrounded midpoint anchors a Mercator meter field, computed in float64 before wrapping its origin at 8192 m. Two periodic lattices span about 410 m and 161 m. Glyph uniforms `u_cloudCover`, `u_cloudSeed`, `u_cloudDetail`, `u_meterOrigin`, `u_meterStep` and `u_cloudOffset` sample fractional local grid coordinates, independent of camera, density and DPR. Positive downwind displacement is subtracted from the sample position, advances only on already-required watched draws and clamps elapsed time to 0.25 s. Visibility, reduced-motion and context transitions rebase its timestamp. Clouds request no animation frames. Cover commits with lighting when its delta exceeds 0.01; fresh moonlight is multiplied by `1 - 0.8 * cover`. Resolved storm cover is 1 independently of Life and reduced motion. Ambient material and background are attenuated before artificial lighting, including reconstructed fills; labels return first. High/Crowd retain detail when the fine lattice spans at least four device pixels, accounting for DPR; undersampled views and Effects/Pixels use uniform half-strength cover dimming. Night, full overcast and nearly clear detailed views bypass spatial noise. No new textures or passes.
- **Rain** (`RAIN`, `rainDrop`): with a storm, the glyph pass draws sparse streak cells falling `RAIN.speed` cells a second and drifting with the wind's x, in a glyph slanted by it (`theme.ts rainGlyphs`), over a slightly dimmed map. Rows are taken modulo `RAIN.wrap` first.
- **Shadows and light ink** (`SHADOW`, `shadowAmount`, `contactShade`, `cellLight`, `LIGHT_INK`): the select pass writes each cell's light to `shadeTex` (RG8, LINEAR, `glyphFbo` colour attachment 1; reads of the glyph target name attachment 0) as `shadeTexel`: green is the cell's own light, red the light the ground would get there (the same on ground). `shadowAmount` casts three rays toward the sun (`u_sun`, from `life/sun.ts solarPosition` or `fixedSun`; `u_sunStep` in cells per meter): the centre and `SHADOW.spread` cell widths to either side (`u_sunSide`), over `SHADOW.steps` near cells and, when a `SHADOW.tall` blocker's shadow would reach past them, `SHADOW.farSteps` far samples; no sample is beyond `SHADOW.reach` (60 m). Each ray takes its strongest blocker taller than the cell, `smoothstep(-soft, soft, (h - self) - d * tan)`, and the rays average. `contactShade` counts ring-1 and ring-2 neighbours at least `SHADOW.aoRise` meters taller (ring 2 at half weight) times `SHADOW.ao`; standing cells (a building, crown or tree with a height; height-zero grounds and terrain bands are ground) take none. `cellLight = (1 - dark * shadow) * (1 - contact)`, 1 with the `shadows` knob off; at night only contact shade remains. The glyph pass multiplies background, same-class fill, colour and focus fill by it, with one texture sample per pixel (`pixelLight`): standing cells (`STANDING_STATE`, bit 3 of the state byte) read green at their cell's centre, and ground pixels read red filtered at the pixel. On a sub-cell edge only the pixels whose sample stands (the crown, or a `u_standing` class with a height: `pixelStands`) read green, so a roof edge cell's ground sextants keep the ground's light; only edge pixels pay that sample lookup. A standing cell's red is its light as ground (shaded by its own building and walls), so filtering toward a sunlit roof cannot lift the shade at its foot. Under SwiftShader, the software WebGL CI renders with, the glyph pass took about 400 ms a frame at 1280x720 in a local check, so this one sample matters: two samples plus a per-pixel standing lookup cost about 45 ms there and slowed CI browser tests by about 10%. Grass and planting take a density light, `mix(lampInk, cellLight * cloud, daylight)` at the cell centre (`densityLight`; the cloud factor and the lamp gates are the glyph pass's own `cloudGlsl` and `lampGlsl`; unclaimed spill, dead lamps and brake glow give none), and shift their tuft score by `LIGHT_INK.gain * (light - neutral)`, capped at one rank of `GRASS_RANKS` either way. Neutral (clear noon on open ground) leaves them as before; gusts, tones and bare planting patches are unchanged. The state byte: bits 0-1 hover/highlight/selected, 2 sub-cell edge, 3 standing (`STANDING_STATE`), 4-5 wind level (`WIND_SHIFT`), 6-7 tone (`TONE_SHIFT`). Frame order: crowns, Life packing, lights and effect clocks, `frameLighting` (one uniform payload for both passes), select, fixtures, glyphs. Neither Life nor `lightPass` reads select output, and light requests no frames of its own.
- **Birds in trees:** the worker emits each tree point in a tile as a perch (`LifeGeometry.perches`, at most `MAX_TILE_PERCHES`). A flock picking where to go next flies to a tree with chance `PERCH.chance` and sits in it, still; `LifeWorld.step` takes a `gustAt(lng, lat)` (strength × `treeGust` on the grid's cells), and a gust over `PERCH.flush` flushes the flock, which scatters for `PERCH.scatter` seconds.
- **Cursor interactions:** Optional trailing `FrameInput.step.pointerRest` (seconds since CSS movement) and `gust` (geographic centre, east/south direction, strength and metre radius) share the worker/inline `LifeWorld.step` path with `pointer`; neighborhoods reuse occupancy, while main-thread wind/ripple anchors are projected relative to each render grid before Float32 upload.
- **Bird mouse avoidance:** `FrameInput.step.pointer` carries mouse lng/lat into `LifeEnv.pointer`; `BIRD_POINTER` uses three cells and twice the normal flight step. Resting flocks use `max(wary, cells × cellMeters)` plus their exact rendered extent, with individual staggered takeoff positions. Nearby airborne members retain independent positions, headings and speeds in `Bird.flight`; `bird-flight.ts` bounds their acceleration and turns, routes them around the pointer, then rejoins the moving formation. Their navigation anchor uses the normal formation plus banking room rather than an expanding envelope of escaped birds. Shared offset arithmetic drives actual rendered positions and extent, and in-view members remain visible when that anchor leaves the view. `BIRD_FLIGHT` sets the steering rates. No physical RNG draws are added; the pointer is absent in replays and untriggered pointer-free state remains unchanged.
- **Birds on the ground:** incremental `TileLife.prepare` cooperatively prepares metric forage terrain before admission. WeakMap caches distinguish geometry, scale and `standalone`/`world` modes: standalone tiles index buildings locally, while world tiles use `setForageGuard` against shared building and seasonal terrain through the tile-origin transform. Guard replacement rechecks remaining movements, retains safe targets and flushes unsafe flocks. `forageChecks` counts suitability and movement decisions; accepted movements interpolate without further terrain queries. A separate seeded stream (`0x4f1bbcdc`) drives feeding, rests and local movements. Ground birds do not reserve space in shared ground occupancy.
- **Labels** draw `labelText(name)`: NFKC (`Ⅱ` → `II`) and ASCII punctuation, so names fit the label atlas; search folds with NFKD for the same reason.
- **Terrain:** DEM luminance → `. : - = + * # %` ramp (Region level only).
- **Priority:** when several classes fall in one cell, a fixed priority order decides (label > landmark > road > building > water > tree crown > area > grass > terrain). Individual crowns and tree rows are an exception: the crown pass reads the cached base class and height at both resolutions, overriding depth over roads and over roofs/building parts lower than the crown. Equal-height roofs win, and overlapping crowns resolve by height. Heights are the existing rounded height bytes, including pipeline defaults. Road connectivity, curbs, and roof walls consult the base geometry beneath crowns so their outlines do not follow the leaves. Edge selection compares crown and roof heights; non-bird Life compositing checks the visible 2×3 surface samples so trunks, crowns, and woods conceal only covered agent pixels. Trunk point cells remain wholly opaque to non-bird Life; birds render above foliage. Occlusion changes drawing only, so simulation continues underneath. Woodland polygons retain their existing boundaries and priority.
- **Road strips (Place level):** from `ROAD_AREA_ZOOM`, carriageways are drawn as strips of their real width (built in the worker) instead of lines; road cells next to a non-road cell become curbs via the same wall mask, with "outside" meaning any class that is neither road nor see-through.
- **Roof surfaces:** detailed fill meshes optionally carry four Int16 values per vertex: local along/across meters, half ridge length and end scale. Each mesh carries a distance scale (normally 1/64 m per step, enlarged for long-range coordinates); end scale uses 1/32767 steps. Positive end scales that would round to zero, or scales outside the packed range, retain a Float32 fallback. This halves ordinary roof surface transfers from 16 to 8 bytes per fill vertex. Frames are computed once per building/leaf and written directly, with no unused ridge-distance work. Ground meshes allocate a zeroed typed ridge buffer directly; only crowns need temporary nonzero reach values. Mesh finalization preserves position clamping without per-element conversion callbacks. Crowns retain their separate two-component surface attribute. Gables have no end slope; hips shorten the ridge by half-width; pyramids use half-width / half-length for their hip angle. The cell pass encodes side, end, ridge and hip codes (0-7) in the existing alpha byte, and the select pass shades slopes against the physical sun vector. Existing ridge glyphs and the 10-bit atlas are reused. Versioned `roof_plan` partitions use one full-footprint Mercator origin; the worker triangulates the original polygon with holes, clips triangles through the bounded split tree, rounds shared intersections consistently, and preserves feature IDs and original Life footprints. Invalid plans fall back for the whole feature. Ordinary roofs still use tile-local bounds; rectangular roofs crossing tile edges remain a follow-up. Party walls resolve class before attributes/IDs and reuse their cached 3x3 samples for ordinary outlines. At compatible cardinal contacts, only the outer ring extends that cache to 5x5, which connects one western/northern-owned wall to exterior walls. No new render pass, class, flag or texture is needed.
- **Outlines (Place level):** from `OUTLINE_ZOOM`, a cell of an outlined feature is a wall if any of its 8 neighbors belongs to another feature (per `idTex`; paths, statues, and markers are looked through). A wall joins its neighbor in a direction when that neighbor is in the same feature and a cell touching both is outside, which draws corners and concave corners correctly without false junctions in thin buildings. The join mask indexes the single- or double-line wall set. Grounds (no height) are never outlined.
- **Sub-cell edges:** `subcellEdge` mirrors the select shader: only empty cells and areas take part (lines and markers win their cells whole); a building among the samples wins over the grounds, park, or water it stands in; walled features are left to their walls; a full or empty mask keeps the class glyph. The mask's bit `row × 2 + col` is the sample's sixth, from the top left, and indexes `sextantGlyphs`.
- **Classes by zoom:** each class has a zoom band in the shared `CLASS_ZOOM` table (e.g. `monument` from z17, terrain until 9.5); the cell pass crossfades it at the band's edges (see the Phase 2 notes above).
- **Labels:** place names (provinces, cities, subdivisions, smaller places, each with the band `featureZoomBand` gives it), curated landmarks (from z17), street names (tiered by road class and OSM `highway` kind in `streetLabel`: major roads from z14, secondary from z15.5, tertiary from z17.5, other streets from z18, paths from z18.5), and monuments (from z18) are placed greedily with selected and hovered names first, then rank, retained visible names, retained offscreen names, newcomers, and feature id, never overlapping, with a one-cell halo. New text fits the on-screen cells; accepted layouts may extend `KEEP_OVERHANG = 3` label cells beyond the fully visible cell bounds. Rounding means the margin from the physical edge is between two and three cells during a subcell pan. Rotated labels try their road-aligned slot first, then their remembered horizontal fallback and remaining beside slots; other labels try the remembered beside slot first. A global `15 ≤ zoom < 17` exclusion clears all glyphs, rotated street meshes, halos, collisions, and the visible-label list; normal bands apply outside it. Names beside an anchor go below, above, right, or left of it, wrapped at 18 characters. A street's name sits at the middle of its longest straight run, with glyphs rotated to that direction and normalized to an upright reading angle. Run endpoints determine whether the whole word fits; short runs, edge clipping and collisions fall back to horizontal beside placement. Rotated halo bounds reserve the collision grid and a dynamic vertex buffer batches the accepted glyph quads. Street names repeat at `STREET_REPEAT = 45` horizontal label-cell widths, using `hypot(dCol, dRow * labelAspect)`; other names occur once on screen. Repeat ownership is keyed by displayed text across kinds, with the incoming candidate's rank determining its distance limit: street candidates require that spacing from any same-text owner, while non-street candidates use infinity. Focus may reverse the order and therefore the suppression. Only accepted text intersecting the fractional physical viewport claims a repeat name; offscreen retained layouts still reserve collision space. Tile-copy selection prefers onscreen text over ghosts, then deeper source-tile geometry, then retains an eligible accepted copy, then chooses the longest eligible run with geographic tie-breaking. Detail arriving after a coarse copy replaces it when eligible; coarse copies remain a fallback when detail cannot qualify. Visibility uses the first geometrically admissible slot, including fallbacks when the remembered slot no longer fits. Entirely offscreen retained text stays in placement memory but leaves `labelschange`. The visible-label list stays in ordinary rank and feature-id order, independent of placement focus and memory. The event compares its complete payload so renamed labels and replaced anchors are reported even with unchanged feature ids. Collection prepares each tile copy once and retains the winning candidates for placement and focus. Eligibility uses the same numeric geometry as placement without constructing layouts; accepted layouts own their collision and text bounds. Whole-cell admission bounds come from the grid module, while physical visibility includes partial cells. Focus changes reuse prepared candidates and redraw only the overlay, reading but not committing the last cell draw's memory. Cell draws (including those during focus) commit memory. Label placement changes invalidate both hover and speech visibility evidence, including focus-only redraws. A separate snapshot of rendered IDs, slots and geometry detects unchanged focus layouts independently of placement order and durable memory; those layouts skip texture and street-buffer uploads and preserve visibility evidence. Unchanged focus/view/source inputs skip geometry work. The frame emits at most one final visible-label payload after shifting and relabeling; unchanged payloads avoid allocation and serialization. Context-loss clearing remains immediate; no extra cell/crown rasterization or class readback is requested. The ordinary crown animation schedule remains active.

## 5. Time model

- Every feature can carry:
  - `start_year?`, `end_year?`
  - `certainty?: 'exact' | 'circa'`
  - `name_history?: { name, from?, to? }[]`
- The pipeline writes these into tile feature properties.
- **Visibility.** In the cell pass, a uniform `u_year` is compared per feature, and invisible features are discarded. Visibility per feature is `start_year <= year && (end_year == null || year < end_year)`.
- **Transitions.** When the year changes, the previous and next visibility are both rendered. A per-cell mask (`scanOrder(x, y) < t`) decides which one shows, which produces the type-in and dissolve effects.
- **Names.** `name_history` is resolved on the CPU during label placement.
- **Underlays.** Imagery snapshots are pre-baked by the pipeline into grayscale raster tiles per year. The glyph pass samples the underlay luminance for cells with no feature class.

- The city is the path (`/<city>`), and everything else is in the query string.
- Debounced (250 ms) `history.replaceState` for camera changes.
- `pushState` for selections and tour starts, so the back button works.
- Parameters: `lat, lng, z, year, sel, tour, step`. Links from before the map went flat may carry `pitch`, `bearing`, or `mode`; they are ignored.

## 7. Search

- The pipeline emits `<city>.search-index.json` for each city:
  - one entry per searchable feature: `id, name, altNames, type, subdivision, lat, lng, zoomHint`
  - plus a serialized MiniSearch index
- The web app lazy-loads the current city's index on the first `/` press. Search is scoped to the current city.
- Fuzzy matching with prefix search. Diacritics are folded, so "Penafrancia" matches "Peñafrancia".

## 8. Performance budgets

Crowd raster budget: `MAX_THRONG_CELLS = 16,000` final texels at high quality; the four tier factors are 1, 0.7, 0.5 and 0.5. Complete figures roll back when a footprint conflicts or would exceed the cap. Crowd masks add two RGBA32UI texels per ASCII cell and are cleared on event/lifecycle changes.

Crowd geography is zoom-independent. Each event classifies its ground once on a 1 m lattice in Mercator space (`throng.ts` field), in 32×32 m chunks: standing or seated ground, street classification, distance along the route and a facing byte, plus terrain clearance cached per accepted terrain snapshot. Where workers are available, a pool of one to three crowd workers (`throng-pool.ts`, `throng.worker.ts`; cores minus three, beside the main thread and the Life and tile workers) prepares chunks off the main thread, four queued per worker, in the same order: the view and its pan margin nearest the centre first, then the rest of the event. Each worker receives an event once and each accepted terrain (its flat blocked indexes) once, keeps the latest two, and returns the chunk's arrays as transfers; a result for an older terrain never replaces a newer one, and a failed request is asked again. Without workers, or after one fails, chunks prepare on the main thread within 3 ms per frame in that order. A new snapshot rechecks only visible chunks and keeps the previous answer until then. A zoom or pan never reclassifies: each view fits one affine lattice→cell transform and projects the field. Detailed cells admit a figure where the cell centre and corners share one ground class; coarse cells sample at most 8×8 points no closer than 1.5 m into their 16×16 safe-ink mask, skipping empty 4×4 m blocks. Static cells live in typed columns over absolute cells, with a 25% pan margin once the scale stops changing, so integer pans only rebase; progress changes recompute membership only. A Mass crowd has gathered when the Mass starts and drains outside-in over its last quarter; its simulated walkers still arrive along the approaches.

Static event crowds do not occupy simulated agents or receive worker ticks. Figure ink is shared by look (paint, flap, candle, seated and one of eight facings) at a scale quantized to a quarter octave; at most 128 new looks prepare per frame, and until a look is ready at a new scale the same look from a recent scale stands in, so zooming never blanks the crowd. Whole-figure field permission is cached per cell and field version; occupancy and final-texel caps are checked on every draw. A procession's verge crowd gathers ahead of the images, walks beside them and thins once they pass, while the stream fills the road behind; parade and fluvial spectators stay put.

### Frame preparation and diagnostics

The Life worker pipelines simulation one accepted frame ahead of drawing. Agents may appear one frame late at a fast pan's leading edge, but remain registered to the current camera. Worker stages (`step`, `visible`, `clearanceBuild`, `clearanceChecks`, `sync`, `spawn`, `settle`, `terrainRebuild`, `terrainRoads`, `terrainRevalidate`, `terrainEncode`, `replyClone`) merge into the next main-thread sample; replies received between callbacks are retained. `sync` includes tile spawning/settlement and `terrainRebuild` isolates static terrain preparation and revalidation. Worker sync timing is retained until its next frame reply. `spawn` and `settle` split tile admission; `terrainRoads` and `terrainRevalidate` are nested inside terrain preparation. On the main thread, `syncPost` measures posting newly resident tile geometry to the worker (a synchronous structured clone), `terrainSnapshot` measures accepting a terrain reply, `tileUpload` measures GPU submission for arriving tiles (including reload after context restoration), and `lifeLatency` measures posting a frame through receiving it. `FrameProfiler.record` retains these between callbacks. Latency includes queueing and messaging, rather than just CPU time. Only with profiling enabled, `replyClone` measures an extra worker-side structured clone of what a reply copies rather than transfers (the agent string table and sidecars, folklore, procession, tap receipts and signal offsets); it is profiling overhead, not transport latency, and lies outside step/visible timing. On the main thread, `agentDecode` measures decoding an accepted reply's agents.

**Packed Life frames.** The worker packs visible agents into columns (`life/agent-frame.ts`): `Float64Array` numbers (coordinates, `ahead`/`side` points, paint, flap, clocks, seeds, ids), presence and boolean bits, string indices into a per-frame table, and a sparse sidecar holding every other own property (people, lines, cues, lamps, beacons). The numeric buffers transfer with `Comlink.transfer` beside puffs and terrain; the frame stays lossless as fields are added. Train consists stay in the worker as before. The host decodes each accepted reply into fresh agent objects and never decodes rejected replies, so an accepted frame is immutable: pause, hover, speech/cue snapshots and tap capture may keep it, and its owner indices stay correlated, without copying or pinning. `runLifeFrame` and the inline host keep object frames. A held texture frame is keyed on the frozen window (its `toCell`, origin, zoom and DPR) and the accepted frame, never on the pan offset or camera center; theme/atlas, sun, focus, speakers, puffs, terrain, event progress, quality, crowd bounds and unfinished crowd preparation still invalidate it. Brake and beam cone caches key on the window's `world` scale and origin. `packLife` reuses one typed journal (a per-cell stamp with the replaced bytes, owners and speaker members) for every ground agent and crowd figure, and `packFixtures` reuses its owner buffer from its scratch. These stage times are worker CPU measurements and are not included in main-thread `draw` or `callback` CPU time. With the inline fallback, step and visibility timings are nested inside the main-thread draw as before.

Adaptive quality changes drawing only: Auto first thins drawn agents (1,200 → 700 → 500), then disables crown sway, ground wind, shadows, water detail, fish and beams, then caps DPR at 1.25. Every tier caps the drawing pixel ratio: high 2, crowd and effects 1.5, pixels 1.25, so high-DPI screens draw at most 2×. High pins the original drawing settings at that cap; Low pins the last tier. CSS-scheduled simulation clearance and gust coordinates remain independent of drawing DPR. Auto samples the next rAF callback after each draw, including callbacks that skip drawing; idle 30 fps pacing is not an overload signal. A bounded ten-second window requires 45 samples. Sustained p75 intervals above 25 ms for three seconds, or 40 ms for 1.5 seconds, lower quality after input has been quiet for one second. During interaction, a severe hold may step down one tier only when the next tier draws at the same effective pixel ratio, so nothing resizes mid-gesture; pixel-ratio changes and every recovery wait for quiet. An eight-second cooldown and delayed, backed-off recovery trials prevent oscillation. Recovery requires healthy interval and CPU samples, changes no draw cadence, and does not require diagnostic profiling.

- Empty tile meshes have `count: 0`, a null VAO, and no buffers. Drawing and disposal skip them.
- Theme palettes are converted to RGB once per theme change. Vehicle part glyph indices belong to each map glyph atlas, rebuilt for theme, density, DPR, or context changes.
- Crown filtering and matrices are reused while tiles, meshes, zoom, DPR, cell dimensions, grid origin, and target dimensions stay the same. A shift inside a cell does not change a matrix.
- Label grids, collision storage, and packed upload buffers are reused per render target and reset before placing labels again. A separate `LabelMemory` map survives resets and is refilled with accepted slots and their last cell draw's physical text visibility only. Candidate caches and placement memory belong to each atlas/target. Target replacement with unchanged label dimensions and cell size transfers only durable acceptance and previous copy references, including across map-density steps; geometry and upload state are rebuilt. Incompatible label geometry, context loss and disposal release them. Maps do not share mutable buffers.
- `Atlas.setReducedMotion(enabled)` applies a system preference change immediately while preserving saved Life settings. It clears agents and moving lights, stills animated effects, finishes an active flight once at its destination, and resets the simulation step clock before resuming. The web app and HUD subscribe to the same media query.

- `Atlas.setFocus(focus: LegendFocus | null)` accepts copied map-class and Life-group descriptors. `LegendFocus` contains `classes: readonly RenderClass[]` and `life: readonly LifeFocus[]`; groups distinguish traffic, people, vendors, pets, boats, trains and birds even when they share a drawing class. Final merged legend entries carry optional descriptors, keyed in transient UI state by `LegendEntryId`. Equal normalized descriptors avoid redraws. Map membership uses two unsigned 32-bit uniform words (class zero excluded); active focus pulses unless reduced motion is requested. CPU focus survives context recovery, while atlas replacement clears UI focus. Panel hiding and legend collapse leave the mounted legend's subscriptions intact.
- `packLife` accepts one optional final metadata object containing a reusable `Uint32Array` of frame-local owners and a readonly focus-group set. Owners are original agent indices plus one, independent of parked-first packing; zero denotes empty/shadow cells. Full writes replace ownership, line writes block underlying tooltips, and rejected whole-agent journals restore four texture bytes plus the prior owner. Owners never become simulation identities or GPU textures. `lifePass` retains its numeric return and pairs its raster revision with the exact visible-agent array. Life B uses permission mask 79 (vehicle/person/boat/bird/train), focus bit 32, and indicator bit 128; alpha retains existing paint/part/shadow meanings.
- `lifehover` emits `{ label, point }` or `{ label: null, point: null }` in canvas CSS pixels. Candidate ownership and exhaustive simulated names are validated using the existing asynchronous readback queue: one three-read batch obtains the glyph class and pointed subcell class/height. Updates validate captured evidence against current geometry, identity, pointer subcell and candidate label; incomplete batches use the bounded cadence-aware expiry above and respect the queue's eight-read cap. No candidate means no visibility reads. Normal label cells and rotated label/halo quads suppress hover, including dissolved cells. Mouse position changes and stationary-pointer agent changes are evaluated once per frame. Exit/press, Life off, reduced motion, target recreation, unwatched canvas, context loss and disposal clear hover. The UI gives agent names precedence over landmark tooltips without changing picking or cursors.
- Focus halo sampling is bounded to eight neighboring cells and runs only with focus enabled. `u_focusLife` skips neighboring Life texture reads for map-only focus; the receiving pixel's surface and height are sampled once outside that loop. Agent ink and halo share one GLSL surface-permission/canopy predicate; halo receiving cells must also permit the agent. Foreground map ink, its background fill and Life ink focus independently, preventing road focus from colouring traffic or hidden agents from colouring roofs. The halo composes below ink, agents, fixtures, weather and labels. No halo sentinel, new render target, population change, worker payload or geographic data is introduced.
- Back/Forward cancels pending URL writes and restores camera, selection, year (including the default when absent), and the requested tour step paused. Even a step of the currently open tour is restored. History restoration stops old flights and tour holds and does not enqueue a new history write.

`getStats().frameMs` measures CPU submission time. `gpuFrameMs` is a separate, smoothed GPU elapsed measurement in milliseconds, or `null` when disabled, unsupported, awaiting results, or invalidated by a disjoint event. `AtlasOptions.gpuTiming` defaults to false; the web app enables it only when the initial URL requests `debug=1`. Timing uses asynchronous `EXT_disjoint_timer_query_webgl2` queries around rendering commands, sampled at most once per 250 ms with at most four outstanding queries. It waits for availability, discards disjoint results, resets on context loss, and never requests a redraw to collect a sample. The debug overlay labels these counters `cpu` and `gpu`; unavailable GPU timing reads `n/a`.

#### Earlier isolated prototypes

`pnpm perf:life` compares seeded simulation fixtures against a Git revision (`--baseline=<revision>`) or a source snapshot (`--baseline-file=<path>`). It calibrates a shared batch size, discards 250 paired calibration batches, and uses at least 90 warmup batches for each fresh pair. ### Cold startup measurement

`pnpm perf:browser --startup --interleaved --runs=8 --baseline=<absolute export directory> --output=<absolute task-folder>/startup.json` measures the first qualifying tile canvas frame's completed draw submission. It is not a GPU-completion or display-presentation timestamp. The renderer emits `ready` and marks `atlas:ready` once per context generation; `getStats().readyMs` measures from renderer construction. The benchmark measures from navigation using the mark and navigation timing's common `performance.timeOrigin`.

Each arm has eight fresh browser contexts at 1920×1080, DPR 1, high quality, active Life at noon/calm, no reduced motion, and a June 15, 2026 fixed city date. HTTP cache and origin storage (including owned ranges) are cleared. Both page and dedicated-worker traffic use 170 ms latency, 9 Mbps download (1,125,000 bytes/s) and 3 Mbps upload (375,000 bytes/s). Baseline-first and candidate-first pairs alternate. Missing marks, failed navigation and page/worker exceptions fail the measurement. Reports retain raw milliseconds, median, nearest-rank p75, export hashes and machine information.

`--control` compares two logical arms of the current export with the same eight-per-arm protocol. The control spread is the absolute difference of their medians. The shared load-time gate improves over an instrumentation-only pre-task baseline, or increases by at most twice this spread; the absolute 2.5-second first-meaningful-render budget is reported separately. Older exports must first receive exactly the same renderer readiness instrumentation, with no startup optimizations. An intermediate measurement while related load-time work is unmerged does not satisfy the combined gate. The exclusive heavy slot prevents local build/performance contention.

### Continuity review corrections

Replacement admission processes one due tile per accepted step with fair rotation and at most 32 attempts. Its complete-body guard includes overlapping coarse/fine owners in the tile neighborhood; distant populations are excluded. Hidden-by-density residents still reserve admission space. Seeds expire after eight active simulated seconds or sixteen failures, retry no sooner than 0.5 seconds later, and remain frozen while retired. `spawnMargin` computes two CSS cells in meters for both hosts and synchronization; only admission applies the 12 m minimum.

Private activation marks commerce complete only after the full generator finishes. Cancelling its tile set discards touched fresh instances and their terrain references, rebuilding from original seeds, while resident/retired instances are retained. Occupancy construction yields in bounded batches. Worker replies and inline rendering finish before scheduled preparation turns; those turns never activate or step Life. Ready state commits only at the next accepted frame. Consumed activation terrain cache entries are deleted without mutating already published snapshots.

Missing-owner seam waits expire after three active simulated seconds and then defer to existing route endpoint behavior, including one-way terminal holds. Existing but unsafe/full destinations still require successful admission. Destination replacement pools are grouped by kind once; nearest selection uses stable linear scans and membership Sets.

The case supplies the production view/margin context, shifts one column, then simulates 60 seconds; reports include pending births and admission guard builds. `--control` compares the current source against itself. Timings do not establish hardware frame rates.

`pnpm exec tsx packages/renderer/scripts/perf-continuity.ts --runs=5 --output=<task-folder>/preparation.json` measures real worker RPC loading against synchronous preparation of the same corrected populations. Simulation is frozen (`dt=0`) to compare identical activation batches and final population hashes; the report separates preparation CPU, slice p95, activation, reply latency and accepted-frame age. `--control` compares staged preparation with itself.
